# QuillForge project instructions

This file is the local operating contract for work in this repository. It supplements the user's global Codex policy.

## Scope and source of truth

- Product constraints live in `docs/CONSTRAINTS.md`.
- Layering and extension boundaries live in `docs/ARCHITECTURE.md`.
- Required change gates live in `docs/WORKFLOW.md`.
- Codex subagent review triggers and contracts live in `docs/agents/CODEX_HOOKS.md`.
- The machine-readable team, routing, no-launch, and handoff policy lives in `docs/agent-team/workflow-policy.json`.
- Per-slice handoff records live under `docs/handoffs/<handoff-id>/handoff.md`; the index and template are in `docs/handoffs/`.
- Release and packaging rules live in `docs/RELEASE.md`.
- Dependency and license records live in `docs/DEPENDENCIES.md`.
- Record material architectural choices in `docs/adr/`.

If implementation and these documents disagree, stop and resolve the discrepancy before adding more code.

## Working rules

1. Work only in the current checkout. Do not create, select, or operate on Git or Codex worktrees.
2. Preserve existing user changes. Inspect before editing and keep generated files generated by their owning tool.
3. Use `uv` for Python discovery, dependency resolution, environments, and commands. Do not use global `pip install` for project dependencies.
4. Keep Python pinned to 3.12 unless an ADR changes the supported version.
5. Keep the UI responsive. File I/O, indexing, search, parsing, and plugin loading must not block the Qt UI thread in production paths.
6. Keep the editor engine behind an adapter boundary. Application code must not depend directly on QScintilla APIs.
7. Keep plugin APIs explicit and versioned. Do not expose internal widgets or mutable service containers as the plugin contract.
8. Do not add telemetry, network access, or code execution to plugins without an explicit product decision and security review.
9. Update dependency and license records whenever a dependency is added, removed, or materially changed.
10. Prefer the smallest complete change. Avoid speculative abstractions that do not protect a documented extension point.

## Mandatory project agent team

The primary agent is always the **Architect** for this repository. It owns scope, architecture decisions, integration, final diff review, release claims, and the final user handoff. It must load [`docs/agent-team/TEAM.md`](docs/agent-team/TEAM.md) and [`docs/agent-team/acceptance.json`](docs/agent-team/acceptance.json) at the start of every task.

For every material task, the Architect must use the following fixed, bounded team workflow. These roles are project-scoped Codex agents under `.codex/agents/`; they are not autonomous owners of the repository. The roster is always six roles, even when a role has no implementation slice in a particular handoff:

1. **Architect (parent)** — owns scope, architecture, integration, final diff review, verification, release claims, and the final handoff.
2. **Project Manager** — turns the request into scope, milestones, dependencies, risks, and an evidence checklist.
3. **Product** — defines user outcome, in/out of scope behavior, acceptance criteria, and recovery expectations.
4. **Developer 1** — owns domain/application/infrastructure implementation analysis or an explicitly assigned write slice.
5. **Developer 2** — owns presentation/integration/packaging implementation analysis or an explicitly assigned write slice.
6. **Test / QA** — performs read-only deterministic verification planning and authorized checks; startup and visual checks remain unrun under the current no-launch policy, and QA does not create or run unit-test assets by default.

Every role must return a bounded result or an explicit `not-applicable` note. Child work must be non-overlapping and returned as evidence, assumptions, risks, and recommended next action. The Architect remains responsible for resolving conflicts and integrating changes.

Only one agent may write to the shared checkout at a time. Child agents are read-only by default; the Architect must explicitly assign and sequence a single developer write slot when delegation is used. Never create or use a Git/Codex worktree.

The default child-agent route is `luna_max` (`gpt-5.6-luna`, max, Fast). Escalate only a complex unresolved call-chain, concurrency/safety, or high-risk review to `terra_max`; use `sol_medium` only for the hardest unresolved system-wide or adversarial review after Terra evidence is insufficient.

Every material change must finish with the required gates in `docs/agent-team/acceptance.json`, actual evidence for each completed gate, explicit unrun checks and reasons, and the project review hooks described below.

## Permanent no-launch boundary

The current user instruction prohibits starting the QuillForge software. Until the user explicitly reverses that instruction, Codex and all child roles must not launch `QuillForge.exe`, instantiate a Qt application/window for runtime inspection, or perform interactive startup/visual acceptance. Static source checks, JSON validation, compilation, and packaging are allowed. Runtime startup and visual evidence must be reported as user-owned and intentionally unrun.

## Mandatory handoff ledger

Every material change, role transition, or delivery slice must create exactly one Markdown handoff at `docs/handoffs/<handoff-id>/handoff.md` using [`docs/handoffs/HANDOFF_TEMPLATE.md`](docs/handoffs/HANDOFF_TEMPLATE.md). The Architect must update [`docs/handoffs/index.json`](docs/handoffs/index.json) and `docs/agent-team/delivery-register.json` in the same handoff, then run [`scripts/verify_handoff.ps1`](scripts/verify_handoff.ps1) and `scripts/check.ps1`. A handoff is not complete when it only says “done”; it must contain the required sections, actual evidence, unrun checks with reasons, known limits, and a concrete next owner/action.

## Codex review delegation

- Review hooks are Codex workflow triggers, not Git hooks or shell commands.
- The parent agent owns integration, final diff review, and verification.
- Default delegated reviewer: `luna_max` (gpt-5.6-luna, max, Fast).
- Escalate only complex call-chain, cross-module, concurrency/safety, or high-risk unresolved reviews to `terra_max`.
- Use `sol_medium` only for the hardest unresolved system-wide or adversarial review after Terra evidence is insufficient.
- Review agents are read-only by default. They must return evidence, assumptions, unresolved risks, and exact file references; they must not create a worktree.
- Do not declare a change complete until the applicable Codex review hook has produced an evidence record.

## Required verification

Before handoff, run the applicable commands and report their results:

```powershell
.\scripts\check.ps1
```

For packaging changes, also run:

```powershell
.\scripts\package.ps1
```

If a check is not run, state why. Do not claim a release-ready artifact without checking the actual packaged output.
