# BATCH Protocol

## 1. 目的

BATCH 用于把大任务拆成 5-30 个可独立验证的子任务，并在人工审查通过后允许 3 个或 6 个子 Agent 并行推进。

BATCH 不是默认加速开关。共享接口、启动脚本、CMake、主题 token、`MainWindow`、`PanelManager` 等合流点默认串行处理。

## 2. 启动条件

必须同时满足：

- 已有 Specs 或 PRD。
- 子任务之间文件范围不重叠。
- 共享接口、命名、配置和验收命令已写清。
- 失败后可以单独回滚或重做。
- 人工审查通过拆分方案。

## 3. 并行度

| 并行度 | 使用场景 |
|--------|----------|
| 1 | 默认值；共享入口、接口、构建、主题、架构边界 |
| 3 | 中等任务；文件互不重叠，验收可独立完成 |
| 6 | 大任务上限；5-30 子任务已拆清并通过人工审查 |

## 4. BATCH 方案模板

```markdown
# BATCH Plan - <标题>

## 总目标

## 本轮不做

## 共享约定

- 接口：
- 命名：
- CMake：
- QSS token：
- 验证命令：

## 子任务

| # | 任务 | 可改文件 | 禁止文件 | 验收方式 | 并行组 |
|---|------|----------|----------|----------|--------|
| 1 |      |          |          |          | A |

## 合流顺序

1. 先合流共享文档和接口。
2. 再合流独立实现。
3. 最后统一构建、测试和 `EmbedDebug.bat`。

## 冲突处理

- 同文件冲突：停止并行，主 Agent 串行合并。
- 架构冲突：回到 Specs 修订。
- 构建失败：进入 LOOP Debug。
```

## 5. 禁止事项

- 未经审查直接让多个子 Agent 写代码。
- 子 Agent 修改分配范围外的文件。
- 用并行扩大需求范围。
- 并行修改 `CMakeLists.txt`、启动脚本、全局主题 token 或核心入口。
- 把未通过构建的子任务合流为完成。
