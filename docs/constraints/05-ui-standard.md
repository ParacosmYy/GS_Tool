# 05 - UI执行标准

> 本文档是 EmbedDebug 约束体系的第5模块。所有 UI 相关开发必须遵守。

---

## 一、设计目标

- UI 不是“看起来现代”就算完成，而是要让状态、层级、可操作性一眼可检查。
- 涉及构建目录、启动路径、构建脚本变更相关的 UI 工程改造，必须保证 `EmbedDebug.bat` 双击可运行，并且项目只保留 `build/` 单一路径。
- 任何新界面都应能回答三个问题：当前是什么状态、用户能做什么、下一步会发生什么。
- 风格允许演进，但语义 token、状态命名和组件职责必须稳定。

---

## 二、设计 Token 体系

### 2.1 单一来源原则

- 所有主题色、间距、圆角、阴影、字体、动效时长，都必须来自统一 token。
- 业务代码和控件代码不得直接发明新的视觉常量。
- 新增视觉语义前，先检查是否已有可复用 token；没有再补 token，而不是临时硬编码。

### 2.2 必备 token

每个主题至少定义以下类别：

| 类别 | 示例 token | 说明 |
|------|------------|------|
| 背景 | `--bg-page`、`--bg-surface`、`--bg-elevated` | 页面、面板、浮层背景 |
| 文字 | `--text-primary`、`--text-secondary`、`--text-muted`、`--text-disabled` | 文本层级 |
| 语义色 | `--color-accent`、`--color-success`、`--color-warning`、`--color-error`、`--color-info` | 状态和提示 |
| 边框 | `--border-default`、`--border-hover`、`--border-focus`、`--border-danger` | 边界和焦点 |
| 间距 | `--space-2`、`--space-4`、`--space-8`、`--space-12`、`--space-16`、`--space-24` | 间距分级 |
| 圆角 | `--radius-sm`、`--radius-md`、`--radius-lg` | 形状统一 |
| 阴影 | `--shadow-sm`、`--shadow-md`、`--shadow-lg` | 层级表达 |
| 动画 | `--motion-fast`、`--motion-normal`、`--motion-slow` | 动效时长 |
| 字体 | `--font-ui`、`--font-mono`、`--font-size-sm`、`--font-size-md` | 排版统一 |

### 2.3 检查规则

- 主题文件必须能导出同一组语义 token。
- 新控件如果要新增颜色或间距，优先复用已有 token。
- 只有当现有 token 不能表达语义时，才允许新增 token。
- 不允许出现“某个控件自己定义一套颜色体系”的情况。

## 三、状态命名体系

### 3.1 统一状态名

状态命名必须可直接用于代码、样式和文档对齐。推荐使用以下状态名：

| 状态名 | 含义 |
|--------|------|
| `default` | 默认态 |
| `hover` | 悬停态 |
| `pressed` | 按下态 |
| `focus` | 焦点态 |
| `selected` | 选中态 |
| `active` | 激活态 |
| `disabled` | 禁用态 |
| `loading` | 加载中 |
| `success` | 成功态 |
| `warning` | 警告态 |
| `error` | 错误态 |
| `empty` | 空状态 |
| `collapsed` | 收起态 |
| `expanded` | 展开态 |

### 3.2 使用规则

- 同一类组件必须使用同一套状态名，不允许同义词混用。
- `selected` 和 `active` 必须区分：`selected` 表示当前选中项，`active` 表示运行中或正在生效。
- `hover`、`pressed`、`disabled` 必须可在样式层直接检查到。
- 空状态、加载态、错误态都属于可见状态，不能被当作“临时提示”草草处理。

## 四、布局与间距

| 元素 | 默认值 | 可接受范围 |
|------|--------|------------|
| 工具栏高度 | 36px | 32-40px |
| 导航树宽度 | 240px | 180-320px |
| 面板内边距 | 12px | 8-16px |
| 控件间距 | 8px | 6-12px |
| 分组间距 | 16px | 12-24px |
| 按钮最小高度 | 32px | 28-36px |
| 输入框高度 | 32px | 28-36px |
| 状态栏高度 | 26px | 24-28px |
| 搜索栏高度 | 34px | 32-40px |
| 基础圆角 | 6px | 4-8px |

### 4.1 规则

- 同一页面里，同类组件的尺寸应保持一致。
- 不允许为了局部视觉效果，随意打破间距 token。
- 如果某个布局需要偏离默认值，必须说明偏离原因。

## 五、排版规范

| 区域 | 推荐字体 | 推荐字号 |
|------|----------|----------|
| UI 正文 | `Microsoft YaHei UI` / `Segoe UI` | 12-13px |
| 终端文本 | `Consolas` / `JetBrains Mono` / `Source Code Pro` | 13-14px |
| 面板标题 | UI 字体加粗 | 13-14px |
| 辅助说明 | UI 字体 | 11-12px |

### 5.1 检查规则

- 正文字体和等宽字体必须分场景使用，不能混用。
- 同级文本必须保持字号层级稳定，不允许一处 12px、一处 13px 随意漂移。
- 长文本需要换行策略，不能依赖控件默认行为碰运气。

## 六、动画规范

### 6.1 基本原则

- 动画必须服务于状态变化、层级变化或操作反馈。
- 动画时长和缓动必须来自统一 token 或统一表。
- 禁止为了“好看”添加没有语义价值的动画。

### 6.2 动画表

| 动画名 | 场景 | 默认时长 | 缓动 | 说明 |
|--------|------|----------|------|------|
| `panel-enter` | 面板切换进入 | 250ms | `OutCubic` | 从右/下进入或淡入 |
| `panel-exit` | 面板切换退出 | 200ms | `InCubic` | 收起或淡出 |
| `search-open` | 搜索栏展开 | 200ms | `OutCubic` | 控制输入聚焦感 |
| `search-close` | 搜索栏收起 | 150ms | `InCubic` | 退出可见层 |
| `toast-enter` | 提示进入 | 300ms | `OutBack` | 仅用于轻提示 |
| `toast-exit` | 提示消失 | 250ms | `InCubic` | 自动隐藏 |
| `selection-move` | 导航/列表选中移动 | 220ms | `OutCubic` | 指示当前焦点 |
| `theme-fade` | 主题切换 | 300ms | `InOutCubic` | 过渡 QSS 切换 |
| `progress-loop` | 进行中进度 | 2000ms | `Linear` | 循环型状态 |
| `pulse-state` | 连接中/活动中 | 1500ms | `InOutSine` | 状态呼吸 |

### 6.3 动画规则

- 动画实现优先使用 `QPropertyAnimation` 或等效 Qt 动画系统。
- 禁止用 `QTimer` 手搓插值来模拟动画。
- 默认只允许一层主动画加一层轻微辅助动画，避免互相打架。
- 需要统一的场景，必须复用同一动画定义，不要每个控件各写一套。
- 动画不足 100ms 或超过 500ms 都需要说明原因。

## 七、组件设计规范

### 7.1 职责边界

- 一个组件只解决一类问题，不允许“既负责布局、又负责状态、又负责业务处理”。
- 重复职责实现必须收敛到公共组件，不能在多个页面里复制粘贴一份近似逻辑。
- 如果两个控件的代码只有命名不同、行为几乎相同，应优先抽象共享基类或共享 helper。
- Serial Station 的 `ui/` 面板只负责显示和发出用户意图 signal，不允许拼接 `QByteArray` 协议帧、不允许解析协议、不允许直接写日志文件。

### 7.2 按钮体系

| 类型 | 外观 | 场景 |
|------|------|------|
| `primary` | 实心 accent + 白字 | 发送、确认、连接 |
| `secondary` | accent 描边 + 透明背景 | 清除、导出、切换 |
| `danger` | 实心 error + 白字 | 断开、删除、取消高风险动作 |
| `ghost` | 无边框 + 次级文字 | 折叠、辅助入口 |
| `disabled` | 低对比度 + 不可交互 | 条件不满足 |

按钮至少要具备 `default`、`hover`、`pressed`、`disabled` 四种状态定义。

### 7.3 输入框

- `default`：背景、边框、文字都来自 token。
- `focus`：必须能看出焦点，不允许只靠轻微颜色漂移。
- `error`：必须和普通焦点态区分明显。
- `disabled`：必须降低对比度并禁止交互。

### 7.4 导航树

- 选中态必须可见，通常包含背景变化和视觉指示条。
- 悬停态不能与选中态混淆。
- 导航项图标、文字、状态标识应遵循统一布局，不允许各页面自由发挥。

### 7.5 状态栏

- 状态栏只负责展示当前会话状态、吞吐量、连接名等摘要信息。
- 不允许把业务操作按钮大量塞进状态栏。

### 7.6 通知吐司

- 吐司只用于短时反馈，不承担确认和决策职责。
- 成功、警告、错误三类通知必须能从样式上区分。

---

## 八、`objectName` 和 `tr()` 规则

### 8.1 `objectName`

- 所有 `QWidget` 都必须设置 `objectName`。
- `objectName` 需要稳定且语义明确，不能使用无意义数字后缀来代替职责。
- 如果控件是 QSS 依赖对象，必须保证 `objectName` 的命名在代码和样式文件中一致。

### 8.2 `tr()`

- 所有用户可见文字都必须用 `tr()` 包裹。
- 包括按钮文案、菜单文案、对话框文案、提示文案、空状态文案和错误文案。
- 如果文字可能被外部用户看到，就按可翻译资源处理，不要例外。

---

## 九、面板切换与过渡

- 面板切换必须有过渡动画，禁止突然闪现或瞬间消失。
- 过渡动画应同时表达“当前内容退出”和“新内容进入”，但不允许堆叠过多动画层。
- `BasePanel`、页面容器、弹出面板之间必须使用统一过渡节奏。
- 切换过程中不允许让用户误以为界面卡死，因此需要明确的加载或过渡状态。

---

## 十、BasePanel 容器规范

### 10.1 定位

`BasePanel` 是所有可切换面板的标准外壳组件，负责统一标题栏、折叠行为、空状态入口和基础视觉层级。

### 10.2 结构

```
┌────────────────────────────────────────┐
│ [icon 16px] 标题文字              [▼]  │
├────────────────────────────────────────┤
│                                        │
│              内容区域                  │
│                                        │
└────────────────────────────────────────┘
```

### 10.3 规则

- 标题栏高度、图标尺寸、折叠按钮尺寸必须来自 token。
- 折叠态和展开态必须有明确状态名。
- 折叠动画必须使用统一动画表，不允许每个面板各写各的时长。
- 以下场景不适合套用 `BasePanel`：始终可见的终端、overlay 搜索栏、固定底栏。

## 十一、层级与阴影

### 11.1 层级定义

| 层级 | 适用场景 | 说明 |
|------|----------|------|
| `elevation-0` | 背景、导航树、工具栏 | 与基底齐平 |
| `elevation-1` | 普通面板 | 轻微浮起 |
| `elevation-2` | 弹出层、搜索栏、Popover | 明确覆盖内容 |
| `elevation-3` | 模态对话框、Toast | 顶层反馈 |

### 11.2 使用规则

- 同层级组件应使用相同阴影 token。
- 层级变化必须和交互语义一致，不能只为了“看起来有立体感”。

---

## 十二、响应式布局规则

### 12.1 断点定义

| 窗口宽度 | 导航树行为 | 面板行为 | 说明 |
|----------|-----------|---------|------|
| `>= 1200px` | 正常显示 | 正常显示 | 桌面完整体验 |
| `900-1199px` | 默认展开，可折叠 | 正常显示 | 小桌面 / 大平板 |
| `< 900px` | 自动折叠为图标栏 | 面板标题弱化或隐藏 | 小窗口 / 平板 |

### 12.2 规则

- 断点切换必须有明确过渡，不允许布局突然跳变。
- 小屏模式下，优先保证可用性，不追求把完整桌面布局强行缩到小屏里。
- 用户手动调整过的偏好应能被保存，但不能破坏断点策略。

## 十三、UI 骨架归属

- 新增 UI 能力优先复用 `src/core/widgets/` 的公共壳层，不要在业务模块里重复写一份相似 UI。
- 未来 UI 能力如果暂时没有明确归属，先在 `src/features/` 或对应架构说明里写清落点，再决定是否创建实现目录。
- 新 UI 文件必须先确认 `objectName`、token、状态名和动画归属，再开始编码。
- Serial Station 专用 UI 放在 `src/apps/serial_station/ui/`，命名为 `SerialPortPanel`、`SerialProtocolPanel`、`SerialCommandPanel`、`SerialLogPanel`、`SerialStatusBar` 等。
- Serial Station UI 只连接 `SerialStationController` 暴露的 slot/signal，不直接 include `core/SerialManager.h` 或具体协议头文件。

### 13-A Serial Station UI 面板边界

| 面板 | 允许职责 | 禁止职责 |
|------|----------|----------|
| `SerialPortPanel` | 串口号、波特率、打开/关闭按钮、连接状态输入 | 直接调用 `QSerialPort` 或 `SerialManager` |
| `SerialProtocolPanel` | 协议选择、设备地址、模式配置 | include 具体协议实现或解析 bytes |
| `SerialCommandPanel` | 指令输入、快捷命令按钮、发送意图 signal | 拼 Modbus/custom 帧 |
| `SerialLogPanel` | 收发日志展示、过滤、清空、导出按钮 | 直接写文件 |
| `SerialStatusBar` | 当前会话摘要、吞吐量、错误状态 | 处理业务状态机 |

## 十三、主题文件

主题文件保持三套：

- `resources/themes/dark_terminal.qss`
- `resources/themes/modern_dark.qss`
- `resources/themes/light.qss`

### 13.1 同步规则

- 三个主题文件必须导出同一组语义 token。
- 新增控件样式时，必须同步检查三套主题的可用性。
- 不允许出现“某个主题能用、另一个主题缺 token”的情况。

### 13.2 检查清单

- 所有颜色都来自 token。
- 所有控件都有明确状态样式。
- 所有可见文本都经过 `tr()`。
- 所有 QWidget 都有 `objectName`。
- 所有面板切换都有动画。
- 没有重复职责实现。
