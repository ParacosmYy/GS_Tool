# 05 - UI 标准与交互规范（重构版）

> 适用范围：`python/embeddebug/` 下 PyQt 界面相关代码；历史 UI 只作为迁移参考，不作为活跃实现入口。

---

## 一、可用性底线

- 所有用户可见文本必须走 PyQt 翻译入口或集中常量，避免散落硬编码。
- 界面新增控件必须有 `objectName`。
- 按钮/输入框/状态提示要有可感知反馈（包括 success/error/disabled）。
- 非模态耗时任务需要明确状态（进行中、成功、失败）。

### 1.1 量化可视化指标

- 关键页首屏状态恢复时间 < 1s（按日志观察）。
- 错误提示可在 3 秒内定位。
- 列表、日志、状态区必须有空态文案。

---

## 二、主题与样式

- 禁止在控件逻辑中硬编码颜色。
- 样式通过 `resources/themes/*.qss` 与主题 token 控制。
- 主色、强调色、错误色由 QSS 与状态类统一管理。
- 深色/浅色样式一致性必须同步检查，新增 token 不得仅单主题适配。

---

## 三、布局与可视化

- 倾向“能理解的布局”，避免纯堆叠。
- 关键数据区优先采用分区信息密度高、视觉分层明确的布局方式。
- 列表/日志/日志计数/状态区必须支持清晰空态（Empty state）。
- 图表控件要考虑刷新速率与采样压缩策略，防止 UI 卡顿。

### 3.1 体验指标

- 连续刷新 UI 下无明显闪烁与抖动。
- 关键控件位置在窗口重排后保持可达。

---

## 四、交互行为

- Enter 回车：触发主要动作（如发送、确认）
- Esc 退出/取消：关闭临时面板
- 快捷键必须有可 discoverable 显示（提示、Tooltip 或帮助文档）
- 所有危险操作必须有确认路径（二次确认/撤销）

### 4.1 输入反馈要求

- 提交行为需要提交中、提交成功、提交失败 3 档可见状态。
- 输入错误需字段级提示，不得仅弹窗。
- 长任务需有暂停、取消或中止。

---

## 五、串口工站 UI 专项

- UI 层只发意图信号，不直接调用协议解析和串口底层发送。
- 日志和状态刷新必须通过 controller 与服务层转发，保持层级清晰。
- 字段可视化（测量、图表）与控制（按钮、快捷命令）分离，避免控制与显示耦合。
- 视图刷新需保证边界保护：空日志、断连状态、空命令、历史为空等边界都要有显示状态。

---

## 六、体验质量要求

- 动画应服务于信息传达，不以“花哨”代替可理解性。
- 数据密集界面需给用户“暂停/继续”与“筛选”能力。
- 错误提示需可读、可定位、可处理。
- 关闭窗口、切换面板、打开重连时的状态必须可见。

### 6.1 可量化验收

- 每轮核心页面至少 3 个关键状态点可观测。
- 状态错误闭环时间需小于 2 次用户交互。
- 非关键路径可在 2 次操作内恢复。

---

## 七、可访问性与国际化

- 控件文本使用 `tr()`，状态、按钮、提示尽量短且明确。
- 输入框 placeholder、tooltip、label 统一语言风格。
- 支持键盘导航优先，不依赖仅鼠标交互。

### 7.1 U 轴计分门禁

- 关键路径无可视反馈：本轮 UI 计分为 +0。
- 关键路径有反馈但缺少恢复动作：不能到 `U3`。
- 关键路径有反馈且可恢复：可达 `U3`。

---

## 八、UI 交付标准（验收）

- 页面功能可操作性达标（`U2/U3`）
- 关键控件有 objectName
- 主题下三种状态可见（normal/hover/disabled）
- 空态文案完整
- 对照约束文档更新对应模块的三轴状态

### 8.1 每次 UI 更改计分条件

- 本次 UI 更改若涉及核心流程，必须至少通过 3 项验收项。
- 关键控件 objectName 缺失：本轮 +0。
- `tr()` 缺失：本轮 +0。

## 九、最小启动 smoke（UI 变更共用）

1. 执行 `uv run test-embeddebug-py`。
2. 执行 `uv run start-embeddebug --smoke`。
3. 执行 `cmd /c EmbedDebug.bat --smoke`。
4. 不可见、闪退或 smoke 失败视为本轮 U 轴阻断。
