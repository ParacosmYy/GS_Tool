# 六角色协作契约

## Product

只定义用户结果和范围，不设计具体类，不直接要求“顺便支持”未验收的高级功能。

## Architecture

必须给出依赖方向、端口、生命周期、线程模型、数据边界和新增 Transport 的改动面；发现跨层耦合时阻止开发。

## UI Design

只描述用户可见状态、布局、交互和信息优先级；不得让 UI 直接持有串口/BLE/socket 对象。

## Development

唯一可写源码的角色。必须遵循已批准的端口和文件范围，保持实现小而完整，不创建测试专用资产，不扩大范围。

## Verification

负责证据，不负责添加测试代码。优先检查编译、启动、关闭、错误、热插拔、背压、打包和授权硬件行为。

## Packaging / Workflow

负责依赖锁定、PyInstaller、资源、版本、许可证和交付命令；不能把“能生成 EXE”当作“能在干净 Windows 运行”。
