## 代码与边界

- `domain/models.py`：`PeerId`、`TcpServerPeerSnapshot`、`TcpServerSend`、`ServerReadResult` 的
  `WRITE_COMPLETED`/`CLIENT_ERROR`、`max_clients` 配置与 IPv4/CIDR 校验；
- `domain/ports.py`：独立 `TcpServerTransportPort`，`send() -> bool` 表示是否接收新的 peer
  write，`wake()` 表示非破坏性唤醒；
- `infrastructure/tcp_server_transport.py`：listener/clients/pending writes/ready results，
  non-blocking socket，读写 readiness，partial offset，round-robin，worker-only close；
- `application/tcp_server_sessions.py`：peer 生命周期、应用 FIFO、in-flight/总字节预算、显式
  `TcpServerSend`、TX completion、peer error/disconnect 事件和 router 隔离；
- `presentation/main_window.py`、`presentation/viewmodels.py`：最大 client、peer target combo、
  `PeerId` 发送、显式选择和目标断开清理；
- 文档：ADR 0005、路线、架构、协议和本记录同步。

## 重要语义

`PeerId` 是一次 accepted TCP connection 的连接代际；`PeerAddress` 不是身份。断开后未发送
队列直接丢弃，旧 ID 发送必须得到 `tcp_server_peer_not_connected`，重连不能命中旧连接。
TCP Server 不做广播、TLS、IPv6、自动重连、可靠重放或应用层送达确认。

## Gate 证据

静态门：

- `uv lock --check`：通过；
- `ruff check --no-cache src`：通过；
- `ruff format --check --no-cache src`：通过（27 files）；
- `uv run --locked python -m compileall -q src`：通过；
- 依赖仍为 Python 标准库 socket/select/threading/deque；未新增 SEGGER/J-Link/probe-rs/RTT 后端依赖。

localhost transport 手工门：

- 两个 client 得到不同 `PeerId`，分别 RX/TX；
- `max_clients=2` 时第三个 client 得到 `busy`；
- 首个连接关闭后其他 peer 仍可 RX；重连得到新 ID；旧 ID 发送被拒绝；
- targeted write 在 completion result 后才可观察到 TX；
- 直接 transport `close()` 释放资源，无残留 client socket。

application/worker 手工门：

- `TcpServerSessionManager` 两 client loopback：显式 target 只到一个 client，产生
  `StreamDataSentEvent`；
- immediate shutdown 和正常 shutdown 最终均为 `closed`，worker 在 3 秒预算内退出；
- client EOF 只移除对应 peer，listener 继续运行。

Qt offscreen 手工门：

- 创建真实 `MainWindow`，切换 TCP Server、绑定动态 localhost 端口并接入两个 client；
- 多 peer 时 combo 初始为无目标，选择一个 target 后仅该 client 收到数据；
- target 断开后 combo 清空，不自动切换到仍在线的其他 client；
- offscreen 最终关闭 session/recorder 成功。
