## Finding and fix

`_preview()` expanded tabs before slicing, but the previous tail-marker check
compared the expanded end position with the unexpanded line length. It could
omit the trailing ellipsis for a tab-expanded line. The old final slice could
also consume a newly appended marker when both leading and trailing markers
were needed.

The fix in `src/quillforge/infrastructure/workspace_search_provider.py` now:

- compares the end position with the expanded line;
- reserves space for leading/trailing markers before slicing the body; and
- handles very small positive preview limits without exceeding the configured
  maximum.

No match collection, path validation, file admission, cancellation, TaskRunner,
dialog, or line-navigation behavior changed.
