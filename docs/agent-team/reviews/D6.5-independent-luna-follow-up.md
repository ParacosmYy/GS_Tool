# D6.5 independent Luna follow-up review

- **Date:** 2026-08-09
- **Delivery:** D6.5 persistent plugin enablement policy
- **Reviewer:** Helmholtz / Luna, read-only
- **Disposition:** ACCEPTED WITH LIMITS; D6.2 dependency repaired

## Direct source review

- `application.plugin_enablement` owns policy resolution and mutation semantics;
  the persistence port keeps paths and storage out of the service.
- `JsonPluginEnablementStore` validates a versioned ID/boolean schema, bounds
  bytes and records, and atomically replaces same-directory state after flush
  and fsync.
- Missing policy preserves a trusted registration's enabled default; corrupt,
  unreadable, or oversized state resolves disabled with a visible error.
- Persistence reloads first and refuses mutation when the ledger is unavailable,
  so an enable/disable action cannot silently overwrite corrupt policy.
- The manager persists trusted lifecycle intent before applying activation and
  external catalog entries never enter the registry.

## Limits

- The review did not launch QuillForge, inspect Qt runtime behavior, run tests,
  or modify files.
- This is local preference state for explicitly registered in-process plugins,
  not publisher trust, signature verification, remote policy, sandboxing,
  installation, or update support.
- D6.6–D6.8 host/security work and power-loss/cross-machine release evidence
  remain open.
