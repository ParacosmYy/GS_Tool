# D8.5 parent review — release handoff freshness

## Scope

- **Delivery:** D8 Enterprise release
- **Slice:** D8.5 artifact-bound handoff freshness
- **Owner:** Architect (parent)
- **Change type:** release-verifier and evidence-dossier hardening

## Decision

The release verifier now writes a current no-go dossier before returning a
failure when a package no longer matches recorded startup or performance
evidence. The current artifact remains visible, the failed check names are
machine-readable, and the process exit remains non-zero.

## Parent audit

- The verifier still validates root/dist identity, manifest identity, notice
  identity, version resources, support routing, and artifact-bound reports.
- `mechanical_failures` is derived only from the existing boolean checks and is
  bounded by the fixed check set; it is not a user-supplied override.
- A mechanically consistent dossier remains `no-go` while release gates are
  open, so the change cannot authorize signing, installation, updates, or
  distribution.

## Limits

- Current startup and performance reports are intentionally stale after the
  latest package because refreshing them would launch the software, which is
  prohibited by the current project instruction.
- This slice does not provide clean-machine, legal, signing, installer,
  update, permission-pressure, hard-power, or cross-machine evidence.

## Disposition

`accepted-with-limits`: the verifier now preserves current artifact provenance
and fails closed on stale evidence; runtime/release gates remain open.
