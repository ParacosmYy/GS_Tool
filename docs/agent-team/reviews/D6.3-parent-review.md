## Parent audit

- `PluginCatalogEntry.descriptor_sha256` is derived only after strict manifest
  validation from a deterministic UTF-8 JSON form with sorted keys and compact
  separators. The digest is displayed as metadata and never resolves the
  entrypoint.
- `PluginApprovalService` owns the approval policy. It accepts only valid
  compatible entries, keys records by `(plugin_id, descriptor_sha256)`, marks a
  changed valid descriptor `stale`, and leaves invalid/duplicate/incompatible
  entries `not-approved`.
- `JsonPluginApprovalStore` owns only the versioned bounded user-local ledger.
  Reads are capped at `max_bytes + 1`, records are capped at `max_records`,
  writes use a same-directory temporary file plus flush/fsync/replace, and
  malformed or oversized state returns an error without granting approval.
  Mutation refuses to overwrite a corrupt ledger.
- `MainWindow` sends approval and revocation through `TaskRunner`, guards the
  scan/governance operation states, and re-scans after a successful mutation.
  The dialog exposes governance actions only; the entry remains
  `trust_state="untrusted"` and `loadable=False`.
- The composition root wires the application service to the port adapter but
  does not scan or execute external extensions during startup.

## Disposition

D6.3 remains `in-progress` because the independent child review is unavailable
in this runtime. The implementation does not claim signature verification,
code identity, dynamic loading, sandboxing, installation, updates, or secure
runtime trust. Approval is governance metadata only.

## Unresolved risks

- No independent child review evidence is available for this increment.
- The canonical digest is an application policy identity, not a cryptographic
  signature or publisher identity; an operator who can replace both descriptor
  and ledger can change the governance result.
- Atomic replacement is validated on the current filesystem path only; power
  loss, permission pressure, cross-machine behavior, and clean-machine startup
  remain unrun release evidence.
- The current packaged and startup evidence is current-machine evidence; the
  release handoff remains `no-go` with the documented signing, installer,
  update, support, legal, and durability gates open.
