# D6.2 follow-up parent review — shared plugin ID length invariant

- **Date:** 2026-08-09
- **Delivery:** D6.2 unified plugin manifest policy
- **Owner:** Architect (parent)
- **Disposition:** ACCEPTED WITH LIMITS

## Trigger

The independent Luna review found that the catalog parser rejected an
oversized `plugin_id`, while the public `validate_plugin_manifest()` did not.
That violated D6-AC02's requirement that registration and catalog
classification enforce the same field-length invariant.

## Fix audit

- `src/quillforge/plugins/api.py` now rejects `plugin_id` values longer than
  `PLUGIN_MANIFEST_MAX_FIELD_LENGTH`, alongside the existing syntax check.
- The catalog parser continues to reuse the public validator after its JSON
  shape checks; no catalog loading or execution path was added.
- Existing valid built-in plugin IDs remain unchanged.

## Evidence and limits

- The Luna read-only review supplied the concrete defect and direct source
  locations; it did not modify files or claim runtime PASS.
- `scripts/check.ps1` and a no-write source probe cover the repaired invariant.
- Trust persistence, signatures, dynamic loading, sandboxing, installation,
  updates, runtime launch, and clean-machine evidence remain open.
