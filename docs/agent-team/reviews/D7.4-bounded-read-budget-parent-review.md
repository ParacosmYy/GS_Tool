# D7.4 scan-time bounded read budget review

- **Delivery:** D7.4 bounded asynchronous workspace search
- **Date:** 2026-08-10
- **Owner:** Architect (parent)
- **Disposition:** ACCEPTED WITH LIMITS; source scan budgets are enforced,
  while packaged/runtime search evidence remains open

## Finding and architecture decision

`FileWorkspaceSearchProvider._search_file()` used `stat().st_size` to admit a
file, then opened and scanned it without a read-time cap. If a file grew
between those operations, the provider could read beyond the configured
per-file and total-byte work bounds. This was a real D7.4 safety-boundary gap,
not a large-file support claim.

The smallest complete fix keeps the application contract and provider search
semantics unchanged. The infrastructure adapter now:

- computes one read budget from the remaining total budget and per-file cap;
- inserts `_BoundedRawReader` at the binary-stream boundary before
  `BufferedReader`/`TextIOWrapper` decoding;
- probes one extra byte only at the boundary to distinguish exact EOF from a
  growing file without counting the probe as scanned data;
- updates actual scanned/reserved bytes and marks `max-file-bytes` or
  `max-total-bytes` only when the read budget is truly reached; and
- explicitly closes the underlying stream through the bounded reader while
  retaining the outer context-manager cleanup.

An exact zero remaining total budget is valid for an empty file: the bounded
reader allows `limit == 0`, performs no body read, and marks a limit only if
the file has grown.

## Simplification assessment

No further behavior-preserving simplification was safe. The one bounded raw
reader is the narrowest central enforcement point that preserves the existing
streaming decoder, UTF-8/UTF-16 behavior, cancellation checks, and application
DTOs. Replacing it with whole-file buffering or duplicating limits in text
scanning would make the boundary less clear or increase memory risk.

## Public-source applicability

This is Python 3.12 desktop filesystem infrastructure, not embedded C/C++,
MCU, BSP/HAL/CMSIS, RTOS, ISR/DMA, driver, protocol firmware, bootloader,
Flash/NVM, power, or motor-control work. The embedded enterprise and embedded
simplifier gates are not applicable; no manufacturer, MISRA, ISO 26262,
certification, or sandbox claim is made.

The stream composition follows the applicable first-party Python 3.12 `io`
contract: [`io` — Core tools for working with streams](https://docs.python.org/3.12/library/io.html),
including `RawIOBase.readinto`, `BufferedReader`, and `TextIOWrapper`.
