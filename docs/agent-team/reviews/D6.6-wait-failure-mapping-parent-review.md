## Trigger and finding

`SubprocessPluginHost.probe()` documents that every child failure is mapped to a
typed `PluginHostProbeResult`. Its call to `_communicate_bounded()` includes
`process.wait(timeout=...)`; the `subprocess` contract permits `OSError` when
waiting on the child and the Popen surface can also report `ValueError` for a
closed/invalid process boundary. Before this slice those exceptions escaped the
probe method instead of becoming a typed child failure.

## Parent repair

The smallest local repair catches only `OSError` and `ValueError` around the
bounded communication call and returns state `crashed` with the launcher PID
and the existing containment status/limits. The communication helper now
best-effort kills/waits after an exceptional wait, closes the output streams,
and joins both bounded reader threads before re-raising the original error for
the typed mapping. The surrounding timeout mapping, protocol parsing,
`execution_enabled=False` invariant, and outer lease/process cleanup remain
unchanged. Protocol violations continue through the existing `protocol-error`
path rather than being relabeled as process crashes.

## Call-chain audit

- `SubprocessPluginHost.probe()` still appends only `--probe` to its fixed
  command and keeps `shell=False`.
- A communication wait failure now returns an immutable application result
  instead of escaping into an untyped TaskRunner error callback.
- The communication failure path closes streams and joins reader threads before
  the existing outer `finally` closes the containment lease and process.
- No plugin payload, dynamic import, external execution, or capability is
  introduced by this repair.
