## Scope decision

QA identified that D7.4 search results exposed only a diagnostic count. The
parent selected a narrow diagnosability increment: preserve the existing
bounded search contract, expose file-level issues through a collapsed read-only
panel, and distinguish a full diagnostic ledger from a ledger that dropped
additional records. No indexing, regex, cross-file replacement, plugin search,
remote root, or performance claim was added.

Product's longer-term recommendation is D7.5 local session continuity. The
Project Manager separately identified the D8.4 license/NOTICE closure as a
release-governance slice. Both remain subsequent deliveries; neither was
silently folded into this source change.

## Implementation audit

- `WorkspaceSearchResult.issues_truncated` is an immutable, validated state;
  it cannot be true without a limited result. `summary()` includes a bounded
  diagnostic-truncation notice.
- The provider sets the state only when its bounded issue ledger is full and
  keeps the primary search limit reason stable. This prevents a secondary
  issue overflow from being silently mistaken for a complete diagnostic set.
- `WorkspaceSearchDialog` projects at most the DTO's bounded issues, uses only
  workspace-relative paths, starts collapsed, resets on root changes, and does
  not participate in filesystem access, TaskRunner scheduling, result
  activation, cancellation, stale-generation handling, or containment checks.
- The packaged Qt-free diagnostic report now includes `issue_records` and
  `issues_truncated`. Its report remains a bounded diagnostic probe, not a
  general command-line search API.
