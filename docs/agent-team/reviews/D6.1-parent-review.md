## Parent audit and integrated fixes

- `JsonPluginCatalogStore.read_candidates` now examines at most 4096 directory
  entries, retains at most 256 JSON manifests, sorts only the retained paths,
  and reports `truncated` when either bound is reached.
- `_read_candidate` rejects symlinks and oversize files and reads at most
  `max_manifest_bytes + 1` bytes after the initial size check, so a file-growth
  race cannot turn the configured byte limit into an unbounded read.
- `PluginCatalogService.scan` owns strict schema/API/permission validation and
  marks every repeated valid or incompatible ID as `duplicate`.
- `PluginCatalogEntry.loadable` is always false and `trust_state` is always
  `untrusted`; the entrypoint is only a validated string and has no import,
  resolution, process, or `PluginManager` call path.
- `MainWindow._show_extension_catalog` schedules the service via `TaskRunner`,
  uses a scan operation ID and in-flight guard, rejects invalid completion
  payloads, isolates scan failures, and projects only an immutable snapshot to
  the read-only dialog.
- Startup composition creates the adapter but does not scan the catalog.
