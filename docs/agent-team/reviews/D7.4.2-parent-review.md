# D7.4.2 Parent Review — TaskRunner lifecycle guard

- **Date:** 2026-08-09
- **Delivery:** D7.4.2
- **Owner:** Architect
- **Disposition:** ACCEPTED WITH LIMITS; source/offscreen contract is complete and
  runtime and broader environment evidence remain open

## Scope

D7.4.2 closes the TaskRunner/MainWindow lifecycle gap identified during the
D7.4.1 review. A submitted task is retained until its single queued completion
slot dispatches success or failure and releases the task. `MainWindow.closeEvent`
uses that retained-task state as its final worker guard, so cancellation state
cannot be mistaken for worker completion.

## Review findings and disposition

The architecture review returned `REVISE` with four findings:

1. The close path retained operation-specific flags in addition to the runner
   state. This is intentional for user feedback and stale-result handling; the
   ADR now identifies the TaskRunner guard as the final submitted-worker
   boundary.
2. Independent success, failure, and cleanup signals could make cleanup order
   observable. The implementation now uses one `completed` signal and a
   `finally` cleanup path.
3. The `_tasks` set needed an explicit ownership contract. Source docstrings
   and the ADR state that it is observed and mutated by the owning UI thread and
   includes both worker execution and queued completion delivery.
4. Direct external destruction and OS termination are outside the normal
   `MainWindow.closeEvent` guarantee. This limitation is recorded in the ADR.

The architecture agent was closed after the revised design was recorded. The
original after-source/simplification workers timed out; a later bounded Luna
source audit returned PASS and is recorded in
`D7.4.2-independent-luna-follow-up.md`. That review closes the independent
source gate; runtime evidence remains open.

## Implementation audit

- `src/quillforge/presentation/task_runner.py` retains `QRunnable` instances
  with `setAutoDelete(False)`, emits one completion payload, dispatches the
  callback, and discards the task in `finally`.
- `src/quillforge/presentation/main_window.py` rejects close while the runner
  reports pending work, including the workspace-cancel window after
  operation-specific state has been cleared.
- The close guard is non-blocking: it does not call `waitForDone()` and does
  not force-terminate worker execution.

## Limits and follow-up

Cancellation remains cooperative and provider-specific. This increment does
not claim immediate interruption, crash-proof shutdown, direct external
destruction safety, or OS-termination durability. D7.5 local session
continuity and D8.4 legal/NOTICE closure remain separate delivery/release
gates.
