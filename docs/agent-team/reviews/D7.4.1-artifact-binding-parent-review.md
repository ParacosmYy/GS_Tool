# D7.4.1 follow-up parent review — packaged diagnostic artifact binding

- **Date:** 2026-08-09
- **Delivery:** D7.4.1 visible bounded search diagnostics
- **Owner:** Architect (parent)
- **Disposition:** ACCEPTED WITH LIMITS; parent source fix packaged

## Trigger

The Luna audit found that the Qt-free `--diagnose-workspace-search` JSON report
contained search results and limits but no identity for the executable that
produced it. A historical report therefore could not be mechanically bound to
the packaged artifact.

## Fix audit

- `src/quillforge/app.py` now emits `execution` and `artifact` fields for
  workspace-search diagnostics.
- Frozen execution hashes `sys.executable` and records its resolved path,
  byte size, and uppercase SHA-256. Source-Python execution explicitly records
  `artifact: null` rather than pretending to be a packaged artifact.
- Artifact hashing failure is represented as a bounded artifact error in the
  report; the search result remains diagnostic-only.
- No search capability, GUI behavior, loader path, or trust boundary changed.

## Limits

- The packaged branch was statically reviewed and included in the rebuilt EXE;
  actual `--diagnose-workspace-search` execution was not run because launch is
  prohibited.
- Historical reports remain historical until a permitted probe regenerates
  them. This does not establish interactive GUI, cross-machine, or performance
  evidence.
- The bounded-directory enumeration-order concern remains a separate tracked
  limitation and is not silently closed by artifact binding.
