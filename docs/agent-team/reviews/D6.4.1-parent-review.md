# D6.4.1 Parent Review

- Date: 2026-08-09
- Delivery: D6.4.1 trust/enablement separation hardening
- Owner: Architect
- Disposition: PROCEED WITH LIMITS; source fixes and deterministic evidence
  are present, but the required post-fix independent review has not returned.

## Team decision

The role loop selected this slice after Developer 1 found a concrete
"enablement grants trust" bypass in `PluginManager.enable()`. Product and
Project Management had recommended closing D7.5.1 first; the Architect
prioritized the higher-risk D6 lifecycle invariant. QA separately recorded
that release remains no-go and that evidence traceability is still an open
engineering concern.

## Findings and fixes

The first implementation only rejected untrusted enablement. The independent
Sol review then identified three additional lifecycle defects:

1. A public enable primitive could bypass a corrupt/oversized enablement
   policy.
2. `set_enabled(..., False)` could persist an unknown ID before raising.
3. Lifecycle status reconstruction reread a plugin-rebindable `manifest`,
   allowing identity and permissions to drift after registration.

The current implementation now:

- exposes only `PluginRuntime.set_enabled()` at the application boundary;
- validates the registered ID and trust before any policy mutation;
- invokes a private enable primitive only after policy persistence succeeds;
- keeps trust immutable and rejects untrusted activation;
- fails unknown IDs before persistence; and
- uses the registration-owned `PluginStatus` manifest/permissions as the
  authority across activation, deactivation, failure, and projection.

## Residual limits

- The runtime is still explicitly registered in-process lifecycle control.
- Local enablement is operator preference, not publisher trust or a security
  boundary.
- External catalog entries remain metadata-only, untrusted, unloaded, and
  non-executable.
- Clean-machine, cross-machine, filesystem-pressure, hard-power, signing,
  installer, update, legal, and support release gates remain open.
