## Parent audit

- `infrastructure.process_containment` owns the OS-specific seam. The
  application layer receives no ctypes types, process handles, or Windows
  constants.
- `WindowsJobObjectContainment` creates an unnamed Job Object, applies
  `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, `JOB_OBJECT_LIMIT_ACTIVE_PROCESS` with
  a two-process launcher/host allowance, and
  `JOB_OBJECT_LIMIT_PROCESS_MEMORY` at 256 MiB per process through the
  documented extended-limit structure. The process is opened with the
  documented assignment rights, assigned immediately, and the process handle
  is closed.
- A failed Windows attach returns a typed failed lease. `SubprocessPluginHost`
  kills/waits/closes the child and returns `containment-error` without sending
  the protocol request. A successful lease is closed in a `finally` block;
  kill-on-close therefore remains the final lifecycle cleanup path.
- `UnsupportedProcessContainment` keeps non-Windows behavior explicit rather
  than fabricating a Windows guarantee. The diagnostic may proceed there, but
  the immutable result says `containment=unsupported`.
- `PluginHostProbeResult` projects containment state, detail, and finite limit
  labels. `MainWindow` continues to invoke the application port only through
  `TaskRunner`; it never sees the platform adapter.
- `execution_enabled` remains false in the host protocol and every result path.
  Approval, enablement, a separate PID, or a Job Object do not activate or
  authorize external modules.

## Unresolved risks

- No independent Terra review evidence is available for this increment.
- Job Object attachment can be rejected by an incompatible parent job or
  environment; the current policy fails closed, but cross-machine coverage is
  not established.
- The two-process allowance accounts for the observed uv launcher/re-exec
  path; it is not a general child-process orchestration policy.
- Job Objects constrain lifecycle/resources but do not replace token,
  filesystem, network, secret, code-identity, or capability-broker controls.
- Clean-machine, cross-machine, permission/disk-pressure, hard-power,
  signing, installer, update, legal, and support release gates remain open.
