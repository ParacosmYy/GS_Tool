- **Delivery:** D7.3, with an adjacent D7.4 report-identity audit

- **Disposition:** ACCEPTED WITH LIMITS; measurement cleanup is repaired and

## Review scope

The parent audited the measurement scripts after identifying that
`scripts/measure.ps1` left `QUILLFORGE_MEASURE_DIR` and `QT_QPA_PLATFORM` in the
calling PowerShell environment. The same cleanup propagation boundary was
checked in `scripts/measure_packaged.ps1`, and the D7.4 packaged search report
and source diagnostic identity path were rechecked without launching the
application.

## Parent findings and change

- `scripts/measure.ps1` now snapshots the caller's location and both
  pre-existing environment values, puts setup and measurement under one
  `try/catch/finally` boundary, records native `uv` failure before preserving
  its exit code, and restores the location and environment independently.
  Source reports now use `artifact: null` plus an explicitly named
  `reference_artifact`; `scripts/repeat_measure.ps1` consumes that source-only
  reference without treating the root EXE as the producing artifact.
- `scripts/measure_packaged.ps1` protects preflight/setup, tracks every child
  process it starts, validates each returned report's execution label, path,
  byte count, and SHA-256 against the producing EXE, and independently attempts
  child-process, temporary-directory, environment, and location cleanup while
  preserving a primary failure.
- `src/quillforge/presentation/diagnostic_runner.py` now labels source versus
  frozen execution explicitly, binds frozen reports to the producing
  executable, and aborts/joins a live recovery worker before temporary
  directory cleanup. Cleanup errors cannot replace an earlier diagnostic
  failure.
- The changes are intentionally limited to cleanup ownership and truthful
  report identity. They do not broaden workload support or reinterpret source
  measurements as packaged performance. The checked-in workspace-search and
  packaged-capture reports predate the current package or lack the current
  artifact binding, so D74-AC04 remains open.

## Independent review

- Luna/max was requested for a read-only review and returned no conclusion
  after three waits; it was closed without a PASS claim.
- Terra/max was then requested under the escalation ladder and returned
  `REVISE`, identifying setup protection, independent restoration, and primary
  failure preservation gaps. The parent applied those corrections. A final
  Terra/max review returned `REVISE` with three remaining findings: preserve a
  native measurement exit code before cleanup, distinguish source diagnostic
  execution from packaged execution, and abort/join a live diagnostic worker
  before temporary cleanup. All three findings were addressed in the current
  source. No child PASS claim is made; the independent evidence is the
  recorded Terra review plus the parent repair audit.

## Simplification assessment

The explicit cleanup attempts are the smallest local change that preserves
temporary-artifact cleanup, child-process/worker shutdown, environment and
location restoration, and primary-error ordering when setup, measurement, or
cleanup fails. Keeping the explicit guards and identity fields avoids a broad
helper refactor or accidental schema ambiguity. No further simplification is
approved for this slice.
