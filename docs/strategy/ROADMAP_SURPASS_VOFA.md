# 需求规格 — EmbedDebug 超越 VOFA+ 路线图

> 状态：需求发现文档（brainstorm 产出），用于指导后续 `/sc:design` 架构设计与 `/sc:workflow` 实现规划。
> 目标：把 EmbedDebug 做成全球第一的串口上位机工具，UI 美化与组件做到完美无缺。
> 技术栈：PyQt6 + pyqtgraph（永久不变，无 native 回退）。
> 迭代方式：持续迭代，无用户命令不停止。

---

## 一、愿景与定位

EmbedDebug 的定位是**面向嵌入式研发、协议调试、硬件联调与产测排障的开源桌面上位机**，
对标并超越 VOFA+。VOFA+ 的核心优势是：直观的波形可视化、简约灵活的数据协议
（RawData/FireWater/JustFloat）、插件驱动的开放控件体系、拖拽式 GUI。

EmbedDebug 要超越它，必须在以下维度做到**领先或对齐**：

1. **波形引擎深度**：百万点不降采样、FFT、直方图、李萨如、独立缩放、富游标测量。
2. **组件丰富度**：LED/滑块/按钮/图片/仪表盘/3D，且可拖拽装配。
3. **协议与传输完备性**：三协议 + UART/TCP-client/**TCP-server**/UDP，且协议插件化。
4. **UI 精致度**：主题、动画、响应式、命令面板、玻璃质感，达到 Linear/Arc 级。
5. **工程化与可维护性**：分层清晰、测试覆盖、打包分发、跨平台。

## 二、差距矩阵（VOFA+ 能力 → EmbedDebug 现状）

| 领域 | VOFA+ 能力 | EmbedDebug 现状 | 差距等级 |
|---|---|---|---|
| **协议** | RawData / FireWater / JustFloat（插件化） | ✅ 三协议全实现 + registry | 对齐（缺插件加载） |
| **传输** | UART / TCP-client / TCP-server / UDP | ✅ UART / TCP-client / UDP / fake；❌ TCP-server | 小差距 |
| **波形-渲染** | 百万点不降采样 + 硬件加速 | ❌ pyqtgraph 自动降采样，无 OpenGL | **大差距** |
| **波形-FFT** | 实时 FFT，点数可设 | ❌ 完全缺失 | **大差距** |
| **波形-直方图** | 实时直方统计 | ❌ 完全缺失 | **大差距** |
| **波形-李萨如** | X-Y 模式（李萨如图） | ❌ 完全缺失 | **大差距** |
| **波形-条形图** | 条形图模式 | ❌ 完全缺失 | 中差距 |
| **波形-缩放** | X/Y 独立 + 同时缩放 | ⚠️ 仅 pyqtgraph 默认鼠标缩放 | 中差距 |
| **波形-游标** | 双击添加/拖拽/删除，X+Y 游标 | ⚠️ 固定 2 个 X 游标，无 Y 游标，无添加/删除 | 中差距 |
| **波形-测量** | 点-点/点-游标/游标-游标 时间差、占空比 | ⚠️ 仅 ΔX + 2 Y 采样 | 中差距 |
| **控件-LED** | 状态灯 | ❌ 缺失 | **大差距** |
| **控件-滑块** | 滑动条 | ❌ 缺失 | **大差距** |
| **控件-按钮** | 可配置控制按钮 | ⚠️ 仅发送/注入按钮 | 中差距 |
| **控件-图片** | 图片显示 | ❌ 缺失 | 中差距 |
| **控件-3D立方** | 3D 立方（可换模型） | ❌ 缺失（需 PyOpenGL） | 中差距 |
| **控件-仪表盘** | Gauge/表盘 | ❌ 缺失 | 中差距 |
| **拖拽 GUI** | 拖拽添加控件，双击全屏 | ❌ 静态三区布局 | **大差距** |
| **插件系统** | 协议+控件插件，开源可写 | ⚠️ registry 存在但无加载发现 | 中差距 |
| **命令绑定** | 控件↔命令优雅绑定 | ⚠️ 仅命令面板+发送行 | 中差距 |
| **UI 精致度** | 简约直观 | ✅ 主题+三区+卡片+图标+动画+命令面板+响应式 | **已领先** |
| **跨平台** | Windows/Linux/MacOS | ⚠️ 引擎可移植，打包仅 Windows | 小差距 |

**结论**：UI 精致度已领先 VOFA+；**波形引擎深度、控件丰富度、拖拽 GUI 是三大硬差距**，
必须优先补齐才能谈"超越"。

## 三、功能需求（按优先级分批）

### FR-W1 波形引擎核心增强（最高优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-W1.1 | **百万点不降采样渲染** | 启用 OpenGL + `setDownsample(auto=False)`，单通道 100 万点 60fps 无卡顿；NumPy ring buffer 承载 |
| FR-W1.2 | **实时 FFT** | 点数可设（256~16384），窗函数可选（矩形/汉宁/汉明），实时频域图刷新无抖动 |
| FR-W1.3 | **实时直方图** | bin 数可设，实时统计分布，与波形同屏 |
| FR-W1.4 | **李萨如（X-Y）模式** | 选两通道做 X/Y 投影，独立缩放 |
| FR-W1.5 | **条形图模式** | 通道值条形展示，适合离散状态 |
| FR-W1.6 | **独立 X/Y 缩放** | 工具栏切换 X-only / Y-only / 同时缩放 |
| FR-W1.7 | **富游标** | 双击添加、拖拽移动、右键删除；X 游标 + Y 游标；多游标 |
| FR-W1.8 | **测量面板** | 游标-游标/点-点 时间差、频率、占空比、峰峰值、均值、最值 |

### FR-C1 控件组件库（高优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-C1.1 | **状态 LED** | 多色（绿/黄/红/灰），可绑定通道值阈值自动变色 |
| FR-C1.2 | **滑块控件** | 可绑定通道值回传命令（协议 build_command） |
| FR-C1.3 | **可配置按钮** | 文本+图标+命令模板，点击发送命令 |
| FR-C1.4 | **仪表盘 Gauge** | 圆弧/指针表盘，可绑定通道值，量程可设 |
| FR-C1.5 | **数值显示** | 大字号实时数值 + 单位 + 趋势箭头 |
| FR-C1.6 | **图片控件** | 显示静态/动态图片（协议推送帧） |
| FR-C1.7 | **3D 立方** | 可换模型的 3D 立方（需 PyOpenGL，可选） |

### FR-D1 拖拽式仪表盘（高优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-D1.1 | **控件画布** | 可放置波形/LED/滑块/仪表盘的画布区域 |
| FR-D1.2 | **拖拽添加** | 从控件库拖拽到画布添加实例 |
| FR-D1.3 | **双击全屏** | 波形/控件双击全屏，再双击恢复 |
| FR-D1.4 | **布局持久化** | 画布布局保存为 JSON，启动恢复 |
| FR-D1.5 | **多画布/标签页** | 多个仪表盘标签页切换 |

### FR-P1 插件系统（中优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-P1.1 | **协议插件加载** | 从指定目录发现并加载用户协议插件（Python 模块） |
| FR-P1.2 | **控件插件加载** | 从指定目录发现并加载用户控件插件 |
| FR-P1.3 | **插件管理 UI** | 列出已加载插件，启用/禁用/重载 |
| FR-P1.4 | **插件契约文档** | 明确协议/控件插件接口与生命周期 |

### FR-T1 传输补齐（中优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-T1.1 | **TCP server** | QTcpServer 监听，多客户端接入 |
| FR-T1.2 | **超高波特率稳定性** | 2Mbps+ 长时间无丢包（需真实设备验证） |

### FR-B1 命令↔控件绑定（中优先级）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-B1.1 | **绑定层** | 控件信号（滑块值/按钮点击）→ protocol.build_command → transport.send |
| FR-B1.2 | **绑定配置 UI** | 可视化配置控件↔命令绑定 |

### FR-U1 UI 精致度持续打磨（持续）

| ID | 需求 | 验收标准 |
|---|---|---|
| FR-U1.1 | **玻璃质感深化** | 卡片磨砂玻璃、毛玻璃模糊（QGraphicsBlurEffect） |
| FR-U1.2 | **微交互** | 按钮波纹、hover 浮起、focus 光环 |
| FR-U1.3 | **主题切换** | 深色/浅色/自定义主题运行时切换 |
| FR-U1.4 | **图标完备** | lucide 50+ 图标全覆盖所有控件 |
| FR-U1.5 | **动画体系** | 统一动画 token（时长/缓动），全应用一致 |

## 四、非功能需求

| ID | 需求 | 目标 |
|---|---|---|
| NFR-1 | **性能** | 单通道百万点 60fps；多通道 10 万点 60fps；FFT 实时无抖动 |
| NFR-2 | **架构边界** | ui/controllers/core/protocols/services/workers/drivers 严格分层；core 不依赖协议；协议不依赖 UI |
| NFR-3 | **测试覆盖** | 每个新组件配套 pytest；关键链路有集成测试；UI smoke 持续绿 |
| NFR-4 | **可维护性** | 单文件 ≤300 行；公共能力复用；零硬编码颜色 |
| NFR-5 | **打包分发** | Windows onedir 稳定；逐步补 Linux/macOS |
| NFR-6 | **文档** | README/PRD/约束文档与代码同步；插件契约文档化 |
| NFR-7 | **持续迭代** | 无用户命令不停止；每批 ≥500 行可独立 commit |

## 五、用户故事

### US-1 嵌入式工程师调 PID
> 作为嵌入式工程师，我想连接设备后实时看到 PID 三通道波形，加 FFT 看频率特性，
> 用游标测量响应时间，一键导出数据，全程不卡顿。

### US-2 电机控制调试
> 作为电机控制工程师，我想用 JustFloat 协议接收高频浮点数据，看李萨如图判断相位，
> 用仪表盘看转速，用滑块下发目标值，所有控件拖拽到一个仪表盘。

### US-3 产测排障
> 作为产测工程师，我想用命令面板快速执行测试命令，看 LED 状态灯判断 pass/fail，
> 日志区记录全过程，导出回放给研发分析。

### US-4 自定义协议扩展
> 作为协议开发者，我想写一个 Python 插件实现我的私有协议，放到插件目录就被发现加载，
> 不用改 EmbedDebug 主线代码。
