## 接口设计

### R1: TerminalWidget 选中坐标系修正

**问题根因**: `setDirectionFilter()` 已调用 `m_selectionManager->reset()` 清除选中，但 `selectedText()` 委托给 `m_selectionManager->selectedText(m_cachedLines, m_directionFilter)`。问题在于 `m_cachedLines` 在方向切换后可能未及时重建（缓存仍为旧方向的数据），导致 `selectedText()` 用旧缓存行提取文本。且在方向过滤切换瞬间，如果用户未重新选中就复制，可能读到空串或错位文本。

**修复方案**: 确保 `setDirectionFilter()` / `clearDirectionFilter()` 中调用 `m_selectionManager->reset()` 后，立即标记缓存脏位，使下次 `paintEvent()` 重建缓存。同时审计 `TerminalSelectionManager::selectedText()` 的行索引映射逻辑。

```cpp
// TerminalWidget.h 新增辅助方法
private:
    /** @brief 将过滤行索引转换为模型行索引 */
    int filteredToModelIndex(int filteredRow) const;

    /** @brief 将模型行索引转换为过滤行索引，返回-1表示该行被过滤掉 */
    int modelToFilteredIndex(int modelRow) const;
```

`selectedText()` 实现中：使用 `filteredToModelIndex()` 将选中范围映射到正确的模型行坐标，再从 `TerminalModel` 提取文本。

### R2: 消除跨帧递归重绘

**问题根因**: `paintEvent()` 中两处（过滤路径 line 288、普通路径 line 311）通过 `QTimer::singleShot(0, this, [this](){ refreshSearchAfterCacheUpdate(); })` 延迟调用搜索刷新。`refreshSearchAfterCacheUpdate()` 内部最终触发 `update()` 形成 `paintEvent → singleShot → refreshSearch → update → paintEvent` 跨帧递归链。虽然 `singleShot(0)` 将调用延迟到事件循环，但在高频搜索输入场景下，每次 `paintEvent` 都注册一个新的 `singleShot` 回调，可能导致 `update()` 调用堆积。

**修复方案**: 将 `refreshSearchAfterCacheUpdate()` 中的 `update()` 调用替换为 `m_searchCacheDirty = true` 标记。在 `paintEvent()` 开头检查该标记并执行搜索缓存刷新，避免注册额外 `singleShot` 回调。

```cpp
// TerminalWidget.h 新增成员
bool m_searchCacheDirty = false;  ///< 搜索缓存需要刷新标记

// TerminalWidget.cpp — 移除 paintEvent 中的 QTimer::singleShot 调用
// 替换为:
void TerminalWidget::paintEvent(QPaintEvent* event)
{
    // paintEvent 入口处理搜索缓存刷新
    if (m_searchCacheDirty && m_searchManager->isSearchActive()) {
        m_searchCacheDirty = false;
        m_searchManager->updateSearchResults(m_cachedLines);  // 纯数据操作
    }
    // ... 原有绘制逻辑（不再注册 singleShot）
}
```

### R3: ChartWidget 空配置→正式配置切换加固

**问题根因**: `onChannelsChanged()` 已有空配置退化路径（line 239-248），用 `m_model->channelNames()` 创建默认 series。但当用户随后通过 `configureFromFrameDefinition()` 配置帧编辑器后，`onChannelsChanged()` 会被再次触发。此时 `m_configSet` 非空，走主路径创建正式 series。问题在于：退化 series 的数据可能未迁移到正式 series，导致切换瞬间数据丢失；且旧 series 的 `QLineSeries` 对象清理可能不彻底。

**修复方案**: 确保从退化→正式配置切换时：(1) 保留退化期间积累的数据点；(2) 正确清除旧 series 并创建新 series；(3) `m_configSet` 更新后立即重建 series。

```cpp
// ChartWidget.cpp onChannelsChanged() 审查并加固
void ChartWidget::onChannelsChanged()
{
    // 保存当前数据点用于迁移
    QMap<QString, QVector<QPointF>> oldData;
    for (auto it = m_seriesMap.begin(); it != m_seriesMap.end(); ++it) {
        const auto& points = it.value()->pointsVector();
        oldData[it.key()] = points;
    }

    // 清除旧 series
    qDeleteAll(m_seriesMap);
    m_seriesMap.clear();

    if (m_configSet.channels().isEmpty()) {
        // 退化路径: 使用 ChartModel 的通道名创建默认 series
        rebuildSeriesWithDefaultConfig();
    } else {
        // 正式路径: 使用用户配置创建 series
        rebuildSeriesFromConfig();
    }

    // 迁移旧数据到新 series（按通道名匹配）
    migrateSeriesData(oldData);
    refreshChart();
}

// 新增私有方法
/** @brief 使用默认通道配置重建 series (默认最多10通道, 自动调色板颜色分配) */
void ChartWidget::rebuildSeriesWithDefaultConfig();

/** @brief 将旧 series 数据迁移到新 series，按通道名匹配 */
void ChartWidget::migrateSeriesData(const QMap<QString, QVector<QPointF>>& oldData);
```

### R4: SerialConnection const_cast 清除

**问题根因**: `SerialConnection::isDtr()` (line 241-245)、`isRts()` (line 248-252)、`pinoutSignals()` (line 481-494) 中使用 `const_cast<QSerialPort&>(m_serial)` 绕过 Qt 6.8.3 的非 const 查询 API（`isDataTerminalReady()`, `isRequestToSend()`, `pinoutSignals()`）。虽然运行时无害（`m_serial` 本身是非 const 的），但 `const_cast` 是代码异味，违反 MISRA/CERT 安全编码规范，且容易在新代码中引发误用。

**修复方案**: 将这三个查询方法改为非 const（移除尾部的 `const` 限定符），直接使用 `m_serial` 的非 const API。同步修改 `IConnection` 基类中对应的虚方法签名。

```cpp
// IConnection.h — 修改虚方法签名（去掉 const）:
virtual bool isDtr() const { return false; }      // 保持 const，但 SerialConnection override 不用 const_cast
virtual bool isRts() const { return false; }       // 同上

// SerialConnection.h — 修改 override 签名:
bool isDtr() override;           // 移除 const，不再需要 const_cast
bool isRts() override;           // 移除 const，不再需要 const_cast
PinoutSignals pinoutSignals() override;  // 移除 const

// SerialConnection.cpp — 实现:
bool SerialConnection::isDtr()
{
    return m_serial.isDataTerminalReady();  // 直接调用，无需 const_cast
}
```

> **注意**: `IConnection` 基类的虚方法仍保留 `const`（默认实现返回 false，无需 const_cast）。`SerialConnection` 的 override 不带 `const`，这是合法的 C++ override（非 const 方法可以 override const 虚方法... 不对，实际上不能。需要改 IConnection 基类为非 const 或使用 `mutable`）。

**最终方案**: 使用 `mutable QSerialPort m_serial` 使 const 方法内可以修改 `m_serial`，或直接将基类和派生类的方法都改为非 const。推荐后者更清晰。

### R5: OtaManager convertHexToBin() 清理路径加固

**问题根因**: `convertHexToBin()` (line 339-388) 已有 `delete m_tempBinFile` 和 `QFile::remove(m_tempBinPath)` 清理逻辑，但存在两个问题：(1) `IntelHex::parse()` 失败的提前退出路径（line 350-355）中不清理旧临时文件——如果上次成功创建了 `m_tempBinFile`，本次 parse 失败后旧文件残留；(2) `setAutoRemove(false)` 意味着应用崩溃后磁盘临时文件永久残留。

**修复方案**: 
1. 在 `IntelHex::parse()` 失败路径中也执行旧临时文件清理
2. 将 `QTemporaryFile` 改为指定 parent（已有 `this`），确保对象生命周期由 Qt 父子树管理
3. 添加析构函数中的安全清理

```cpp
// OtaManager.cpp convertHexToBin() 加固
bool OtaManager::convertHexToBin(const QString& hexPath, QString& outBinPath)
{
    // 清理旧临时文件（移到方法最前面，确保所有退出路径前都已清理）
    if (m_tempBinFile) {
        QString oldPath = m_tempBinFile->fileName();
        delete m_tempBinFile;
        m_tempBinFile = nullptr;
        if (!oldPath.isEmpty()) {
            QFile::remove(oldPath);
        }
        m_tempBinPath.clear();
    }

    QByteArray binary;
    quint32 startAddr = 0;
    if (!IntelHex::parse(hexPath, binary, startAddr)) {
        emit errorOccurred(tr("OTA"), tr("HEX文件解析失败: %1").arg(hexPath));
        return false;  // 旧文件已在上方清理
    }

    // ... 创建新临时文件并写入
}
```

**注意**: `QTemporaryFile` 已经在构造时指定了 `this` 作为 parent（line 359），对象生命周期由 Qt 管理。核心问题是磁盘文件的清理时机。
