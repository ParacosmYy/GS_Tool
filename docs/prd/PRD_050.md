# PRD-050: 架构管理审查 #50 + ZModemTransfer瘦身 + 自动重连配置持久化 + UI一致性修复

## 背景

本次迭代是 commit #50 里程碑，触发 CLAUDE.md 3.3 节强制架构管理审查。同时需要解决 4 个紧迫问题:

1. **架构管理审查（强制）**: 每 5 次 commit 必须执行全面架构审计。上一次架构审查在 PRD-045（commit #45）。本次审查范围: 分层合规、公共组件复用、设计模式合规、模块耦合、include路径规范、目录结构。

2. **ZModemTransfer.cpp 逼近红线**: 当前 498 行，距离 500 行硬上限仅 2 行。任何一个 Bug 修复或小功能增加就会突破限制。必须在本迭代主动瘦身，目标降至 480 行以下。

3. **自动重连配置无持久化**: PRD-049 实现了自动重连上限（maxRetries/intervalMs/enabled），但 `ConnectionController::enableAutoReconnect()` 的三个参数仅存在于内存中。应用重启后自动重连状态全部丢失，用户每次启动都需要重新配置。`SettingsController` 和 `SettingsManager` 已有完整的 save/load 基础设施，只需扩展即可。

4. **FrameVisualEditor 按钮高度不一致**: UI/UX 审查发现 `m_applyBtn`（"应用定义"按钮）设置了 `setMinimumHeight(36)`（第 66 行），而同文件内的"添加字段"、"删除字段"等按钮以及项目中其他主要操作按钮（如"连接"按钮）使用 32px 高度。违反 CLAUDE.md 6.3 节"一致性"原则和按钮高度 28-32px 规范。

### 实现方案

**R8 offsetToBytes()** (ZModemTransfer.h 新增声明，ZModemTransfer.cpp 新增实现):

```cpp
// ZModemTransfer.h private 区域新增:
static QByteArray offsetToBytes(qint64 offset); ///< 将偏移量打包为4字节小端QByteArray

// ZModemTransfer.cpp 新增:
QByteArray ZModemTransfer::offsetToBytes(qint64 offset)
{
    QByteArray data;
    data.append(static_cast<char>(offset & 0xFF));
    data.append(static_cast<char>((offset >> 8) & 0xFF));
    data.append(static_cast<char>((offset >> 16) & 0xFF));
    data.append(static_cast<char>((offset >> 24) & 0xFF));
    return data;
}
```

调用处改造:
- `sendZDATA()`: 替换 5 行为 `QByteArray offsetData = offsetToBytes(m_fileOffset);`
- `sendZEOF()`: 替换 5 行为 `QByteArray offsetData = offsetToBytes(size);`
- `buildBinHeader()` 中的 offset 打包: 如适用

**R9 offsetFromBytes()**:

```cpp
// ZModemTransfer.h private 区域新增:
static qint64 offsetFromBytes(const QByteArray& data); ///< 从4字节小端QByteArray解析偏移量

// ZModemTransfer.cpp 新增:
qint64 ZModemTransfer::offsetFromBytes(const QByteArray& data)
{
    qint64 offset = 0;
    for (int i = 3; i >= 0; --i)
        offset = (offset << 8) | static_cast<quint8>(data[i]);
    return offset;
}
```

调用处改造:
- `handleStateSendingFile()` 第 193-194 行: 替换为 `m_fileOffset = offsetFromBytes(headerData);`
- `handleStateSendingData()` 第 231-232 行: 替换为 `m_fileOffset = offsetFromBytes(headerData);`

**预估节省**: 每处消除约 4 行重复代码 + 1 行新调用 = 净减约 3 行。3 处 offsetToBytes + 2 处 offsetFromBytes = 净减约 15 行。新增 2 个方法约 20 行。总计: 498 - 15 + 20 - (方法声明开销) ~ 约 488 行。如需进一步瘦身，可考虑将 `escapeZdle()` + `toHex()` 移到私有辅助文件。

## 第三部分: 自动重连配置持久化 (P1)

### 现状

PRD-049 实现了完整的自动重连上限逻辑:
- `ConnectionController::enableAutoReconnect(bool enabled, int intervalMs, int maxRetries)` -- 运行时配置
- `m_autoReconnectEnabled`, `m_reconnectMaxRetries`, `m_reconnectAttemptCount` -- 内存成员
- `reconnectAttempt(int, int)` 信号 -- 进度通知
- `onAutoReconnect()` -- 含重试上限检查的完整逻辑

**缺失**: 配置仅在内存中，应用重启后丢失。`SettingsController` 和 `SettingsManager` 已提供完整的 save/load 基础设施，但尚未接入自动重连配置。

### 需要持久化的配置项

| 配置项 | 成员变量 | 设置键名 | 类型 | 默认值 |
|--------|---------|---------|------|--------|
| 启用状态 | `m_autoReconnectEnabled` | `reconnect/enabled` | bool | false |
| 重连间隔 | `m_reconnectTimer.interval()` | `reconnect/intervalMs` | int | 3000 |
| 最大重试次数 | `m_reconnectMaxRetries` | `reconnect/maxRetries` | int | 0 (无限) |

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R11 | **SettingsController 新增自动重连配置保存方法**: `saveAutoReconnectConfig(bool enabled, int intervalMs, int maxRetries)` 将三个参数写入 SettingsManager 的 `reconnect/` 分组 | P1 | core/SettingsController | 调用后 SettingsManager 中 `reconnect/enabled`、`reconnect/intervalMs`、`reconnect/maxRetries` 三个键值正确写入 |
| R12 | **SettingsController 新增自动重连配置加载方法**: `loadAutoReconnectConfig()` 返回包含 enabled/intervalMs/maxRetries 的 QVariantMap | P1 | core/SettingsController | 无保存数据时返回 `{enabled: false, intervalMs: 3000, maxRetries: 0}` |
| R13 | **ConnectionController 构造时恢复自动重连配置**: 在构造函数中调用 SettingsController 加载配置，调用 `enableAutoReconnect()` 恢复上次设置 | P1 | core/ConnectionController | 应用重启后自动重连配置与上次关闭时一致 |
| R14 | **ConnectionController 配置变更时自动保存**: `enableAutoReconnect()` 方法内部在修改成员变量后，通知 SettingsController 保存配置 | P1 | core/ConnectionController | 调用 `enableAutoReconnect(true, 5000, 3)` 后配置自动持久化 |

### 实现方案

**SettingsController.h 新增**:

```cpp
public:
    /**
     * @brief 保存自动重连配置到磁盘
     * @param enabled 是否启用自动重连
     * @param intervalMs 重连间隔(毫秒)
     * @param maxRetries 最大重连次数(0=无限制)
     */
    void saveAutoReconnectConfig(bool enabled, int intervalMs, int maxRetries);

    /**
     * @brief 从磁盘加载自动重连配置
     * @return QVariantMap 包含 enabled(bool), intervalMs(int), maxRetries(int)
     */
    QVariantMap loadAutoReconnectConfig() const;
```

**SettingsController.cpp 实现**:

```cpp
void SettingsController::saveAutoReconnectConfig(bool enabled, int intervalMs, int maxRetries)
{
    auto& s = SettingsManager::instance();
    s.set("reconnect/enabled", enabled);
    s.set("reconnect/intervalMs", intervalMs);
    s.set("reconnect/maxRetries", maxRetries);
}

QVariantMap SettingsController::loadAutoReconnectConfig() const
{
    auto& s = SettingsManager::instance();
    QVariantMap config;
    config["enabled"] = s.get("reconnect/enabled", false);
    config["intervalMs"] = s.get("reconnect/intervalMs", 3000);
    config["maxRetries"] = s.get("reconnect/maxRetries", 0);
    return config;
}
```

**ConnectionController 协作**:

需要在 ConnectionController 中持有 SettingsController 引用（或通过回调/信号通知保存）。

方案A（推荐 - 通过构造函数注入）:
- `ConnectionController` 构造函数新增 `SettingsController*` 参数
- `enableAutoReconnect()` 末尾调用 `m_settingsController->saveAutoReconnectConfig(...)`
- 构造函数末尾加载: `auto cfg = m_settingsController->loadAutoReconnectConfig(); enableAutoReconnect(...);`

方案B（信号通知）:
- `ConnectionController` 新增 `autoReconnectConfigChanged(bool, int, int)` 信号
- `MainWindowSignalConnect.cpp` 中连接该信号到 `SettingsController::saveAutoReconnectConfig`
- 构造时由 `MainWindow` 负责加载

**推荐方案A**: 直接注入，减少信号连接复杂度。SettingsController 已是轻量委托类。
