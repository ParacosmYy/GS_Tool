# PRD-048: 代码质量清扫 -- 方法拆分、路径规范化、去重与防御性校验

## 背景

迭代47完成后，代码审查和QA扫描发现6类代码质量问题，按严重程度排列:

1. **P0 方法长度违规**: 8个方法超过CLAUDE.md规定的80行上限。最严重的`FrameVisualEditor::setupUI`达177行（超出121行），包含5个UI分组、1个按钮区和4段信号连接混在一个方法中。长方法是认知负担的主要来源，也是缺陷滋生的温床。

2. **P1 Include路径违规**: 48处`#include "File.h"`裸引用分散在22个文件中，违反CLAUDE.md 5.1节"头文件引用使用相对src目录的路径"的强制规定。裸引用依赖编译器的include path搜索顺序，在不同构建配置下可能导致错误的头文件被选中。

3. **P1 缺失Doxygen注释**: `TerminalContextMenuManager.h/cpp`的所有signals、methods和members均无Doxygen注释，违反CLAUDE.md 5.1.2节的注释铁律。

4. **P1 OTA协议常量重复**: SOH、EOT、ACK、NAK、CAN、CRC_CHAR六个X/YMODEM协议控制字节在`XModemTransfer.h`（行94-100）和`YModemTransfer.h`（行94-99）中各自定义了完全相同的constexpr值。两处定义互不关联，修改一处时容易遗漏另一处。

5. **P2 ZDLE转义代码重复**: `ZModemTransfer.cpp`中`buildBinHeader`（行373-382）、`buildDataSubpacket`数据段（行389-396）、`buildDataSubpacket` CRC段（行408-415）共三处执行完全相同的ZDLE转义逻辑（检测0x18/0x0D/0x0A/0x11/0x13/0x2A后追加ZDLE+异或字节）。

6. **P2 未校验file.readAll()**: `XModemTransfer::onStartInit`（行79）、`YModemTransfer::loadNextFile`（行485）、`ZModemTransfer::onStartInit`（行63）三处在调用`file.readAll()`后未校验返回的QByteArray大小是否与`QFileInfo::size()`一致。虽然前有大文件上限校验，但在磁盘空间不足或文件被截断的边界场景下，`readAll()`可能返回不完整数据，导致传输静默损坏。

当前评分: 47/1000

## 第四部分: OTA协议常量去重 (P1)

### 现状

完全相同的6个constexpr常量在两个头文件中各自定义:

**XModemTransfer.h (行94-100)**:
```cpp
static constexpr char SOH = 0x01;
static constexpr char STX = 0x02;
static constexpr char EOT = 0x04;
static constexpr char ACK = 0x06;
static constexpr char NAK = 0x15;
static constexpr char CAN = 0x18;
static constexpr char CRC_CHAR = 'C';
```

**YModemTransfer.h (行94-99)**:
```cpp
static constexpr char SOH = 0x01;
static constexpr char EOT = 0x04;
static constexpr char ACK = 0x06;
static constexpr char NAK = 0x15;
static constexpr char CAN = 0x18;
static constexpr char CRC_CHAR = 'C';
```

YModem使用SOH(128字节块)但不需要STX。两者共享SOH/EOT/ACK/NAK/CAN/CRC_CHAR。

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R8 | OTA协议控制字节常量提取: 在`ota/protocols/`目录下新建`OtaProtocolConstants.h`，定义namespace OtaProtocol包含SOH/STX/EOT/ACK/NAK/CAN/CRC_CHAR七个constexpr值，XModemTransfer.h和YModemTransfer.h删除各自定义改为include此头文件 | P1 | ota/protocols | OtaProtocolConstants.h 包含所有7个常量；XModemTransfer.h和YModemTransfer.h不再自行定义这些常量；零编译错误；二进制行为不变 |

### 设计方案

```cpp
// ota/protocols/OtaProtocolConstants.h
#ifndef OTA_PROTOCOL_CONSTANTS_H
#define OTA_PROTOCOL_CONSTANTS_H

/**
 * @file OtaProtocolConstants.h
 * @brief XMODEM/YMODEM协议共享控制字节常量
 *
 * XMODEM和YMODEM共享相同的握手和传输控制字节:
 *   SOH(0x01) = 128字节块起始, STX(0x02) = 1024字节块起始
 *   EOT(0x04) = 传输结束, ACK(0x06) = 确认, NAK(0x15) = 否定确认
 *   CAN(0x18) = 取消传输, CRC_CHAR('C') = CRC模式请求
 *
 * ZMODEM使用不同的帧结构(ZPAD/ZDLE/ZBIN/ZHEX等)，
 * 不共享此命名空间，其常量定义在ZModemTransfer.h内部。
 */
namespace OtaProtocol {
    static constexpr char SOH       = 0x01;  ///< 128字节数据块起始标记
    static constexpr char STX       = 0x02;  ///< 1024字节数据块起始标记(XModem-1K)
    static constexpr char EOT       = 0x04;  ///< 传输结束标记
    static constexpr char ACK       = 0x06;  ///< 确认应答
    static constexpr char NAK       = 0x15;  ///< 否定确认(Checksum模式回退)
    static constexpr char CAN       = 0x18;  ///< 取消传输
    static constexpr char CRC_CHAR  = 'C';   ///< CRC模式请求
}

#endif // OTA_PROTOCOL_CONSTANTS_H
```

XModemTransfer.h和YModemTransfer.h中的使用改为`OtaProtocol::SOH`等限定名。ZModemTransfer.h的常量(ZPAD/ZDLE/ZBIN32等)与X/YMODEM完全不同，保持内部定义不变。

## 第五部分: ZDLE转义去重 (P2)

### 现状

`ZModemTransfer.cpp`中三处完全相同的ZDLE转义代码块:

**位置1 - buildBinHeader (行373-382)**:
```cpp
for (char b : payload) {
    quint8 c = static_cast<quint8>(b);
    if (c == 0x18 || c == 0x0D || c == 0x0A || c == 0x11 || c == 0x13 || c == 0x2A ||
        (c == 0x00 && frame.size() < 8)) {
        frame.append(ZDLE);
        frame.append(static_cast<char>(c ^ 0x40));
    } else {
        frame.append(b);
    }
}
```

**位置2 - buildDataSubpacket数据段 (行389-396)**:
```cpp
for (char b : data) {
    quint8 c = static_cast<quint8>(b);
    if (c == 0x18 || c == 0x0D || c == 0x0A || c == 0x11 || c == 0x13 || c == 0x2A) {
        packet.append(ZDLE);
        packet.append(static_cast<char>(c ^ 0x40));
    } else {
        packet.append(b);
    }
}
```

**位置3 - buildDataSubpacket CRC段 (行408-415)**: 与位置2完全相同。

注意: 位置1比位置2/3多一个条件`(c == 0x00 && frame.size() < 8)`，这是BIN帧头前8字节内0x00也需转义的特殊规则。数据段和CRC段不需要此条件。

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R9 | ZDLE转义辅助方法: 在ZModemTransfer中新增私有方法`escapeZdle(QByteArray& dest, char byte, bool escapeNull)`，封装ZDLE转义逻辑。三处内联代码替换为调用此方法 | P2 | ota/protocols/ZModemTransfer | 三处重复代码替换为方法调用；buildBinHeader传入escapeNull=true；buildDataSubpacket传入escapeNull=false；零编译错误；协议行为不变 |

### 设计方案

```cpp
// ZModemTransfer.h private区域新增:
/**
 * @brief ZDLE转义写入
 * @param dest 目标字节数组(追加写入)
 * @param byte 待转义字节
 * @param escapeNull true时在BIN帧头前8字节内对0x00也做转义
 *
 * ZDLE转义规则: 当字节值为0x18/0x0D/0x0A/0x11/0x13/0x2A时，
 * 或(escapeNull且字节为0x00)时，追加ZDLE + (byte ^ 0x40)，
 * 否则直接追加原字节。
 */
void escapeZdle(QByteArray& dest, char byte, bool escapeNull);
```

## 第六部分: file.readAll()防御性校验 (P2)

### 现状

三处`file.readAll()`调用未验证读取完整性:

| 位置 | 文件 | 行号 | 当前代码 |
|------|------|------|---------|
| 1 | XModemTransfer.cpp | 79 | `m_data = file.readAll();` 后无size校验 |
| 2 | YModemTransfer.cpp | 485 | `m_currentData = file.readAll();` 后无size校验 |
| 3 | ZModemTransfer.cpp | 63 | `m_fileData = file.readAll();` 后无size校验 |

风险场景: 磁盘空间不足导致readAll()返回截断数据；文件在open()和readAll()之间被外部程序修改/截断；网络映射驱动器上的文件读取不完整。传输不完整固件到MCU可能导致设备变砖。

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R10 | file.readAll()返回值校验: 三处在readAll()后比较QByteArray.size()与QFileInfo::size()，不一致时emit transferError并return false | P2 | ota/protocols (XModem/YModem/ZModem) | readAll()后立即校验data.size() == fileInfo.size()；不一致时输出中文错误信息并中止；零编译错误；正常文件读取不受影响 |

### 设计方案

三处统一校验模式:

```cpp
// XModemTransfer::onStartInit (行79后):
m_data = file.readAll();
file.close();
if (m_data.size() != fileInfo.size()) {
    emit transferError(tr("文件读取不完整: 预期 %1 字节, 实际读取 %2 字节")
                           .arg(fileInfo.size()).arg(m_data.size()));
    return false;
}

// YModemTransfer::loadNextFile (行485后):
m_currentData = file.readAll();
file.close();
qint64 expectedSize = QFileInfo(m_filePaths[m_fileIndex]).size();
if (m_currentData.size() != expectedSize) {
    emit transferError(tr("文件读取不完整: 预期 %1 字节, 实际读取 %2 字节")
                           .arg(expectedSize).arg(m_currentData.size()));
    return false;
}

// ZModemTransfer::onStartInit (行63后):
m_fileData = file.readAll();
file.close();
if (m_fileData.size() != fileInfo.size()) {
    emit transferError(tr("文件读取不完整: 预期 %1 字节, 实际读取 %2 字节")
                           .arg(fileInfo.size()).arg(m_fileData.size()));
    return false;
}
```
