# PRD-049: 连接体验增强 -- 自动重连上限、状态指示、DataExporter安全瘦身与网络错误翻译

## 背景

迭代48完成了代码质量清扫（方法拆分、Include路径规范、去重与防御性校验）。本次迭代聚焦连接体验和代码健康度的持续改进，共发现5个需要解决的问题:

1. **P0 自动重连无上限**: `ConnectionController::enableAutoReconnect()` 在头文件中声明了 `maxRetries` 参数，但 `.cpp` 实现完全忽略该参数。`onAutoReconnect()` 内无任何重试计数逻辑，重连定时器会无限触发直到连接成功。当设备彻底离线时，应用会永远在后台反复尝试连接，消耗CPU和日志输出，用户无法得知当前重连进度，也无法得知重连已停止还是仍在继续。头文件第117行还声明了 `reconnectAttempt(int attempt, int maxRetries)` 信号但从未发射。

2. **P1 状态栏缺少重连状态指示**: 用户启用自动重连后，连接意外断开时状态栏仅显示"未连接"。没有任何视觉反馈表明系统正在尝试重连、当前是第几次尝试、还剩几次机会。用户可能误以为自动重连功能失效，手动去点击"连接"按钮。

3. **P1 DataExporter.cpp 逼近500行红线**: DataExporter.cpp 当前 498 行，距离 CLAUDE.md 规定的 500 行上限仅差 2 行。该文件包含全量导出(5个方法)、流式导出(5个方法)、EDL范围导出、辅助方法，以及重复的"打开文件 -> 检查错误 -> 写入 -> 刷新检查"模式。任何新增格式或功能都会突破上限。需要预防性拆分，目标降至 480 行以下。

4. **P2 连接超时硬编码**: `kConnectionTimeoutMs = 5000` 作为 `static constexpr` 硬编码在 `ConnectionController.h` 第151行。不同连接类型的超时需求不同（串口直连通常很快，TCP远程服务器可能需要更长），用户无法根据网络环境调整该值。

5. **P2 网络连接错误消息未翻译**: `SerialConnection` 实现了完整的 `translateError()` 方法（SerialConnection.cpp 第368-398行），将 QSerialPort 错误码翻译为详细的中文描述和操作建议。但 `TcpConnection::onSocketError()`（TcpConnection.cpp 第136-142行）和 `UdpConnection::onError()`（UdpConnection.cpp 第105-111行）直接使用 `socket->errorString()` 输出 Qt 的原始英文错误消息（如 "Connection refused"、"Network unreachable"），未做任何翻译。这导致用户看到的是英文系统错误而非中文诊断信息，与串口连接的体验不一致。

当前评分: 48/1000

## 第一部分: 自动重连上限与重连状态指示 (P0/P1)

### 现状

| 项目 | 当前状态 | 问题 |
|------|---------|------|
| `enableAutoReconnect()` | 接受 `maxRetries` 参数但忽略 | 无限重连 |
| `onAutoReconnect()` | 仅检查 `m_currentConn` 和 `m_userInitiatedDisconnect` | 无计数、无上限检查 |
| `reconnectAttempt` 信号 | 头文件声明但从未 emit | 信号死代码 |
| 状态栏 | 断开后仅显示"未连接" | 重连时无视觉反馈 |
| Toast通知 | 重连过程中无任何通知 | 用户不知道系统在尝试重连 |

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R1 | **ConnectionController 新增重试计数成员**: 添加 `m_reconnectCount` (int) 和 `m_maxReconnectRetries` (int) 成员变量，`enableAutoReconnect()` 中保存 `maxRetries` 到 `m_maxReconnectRetries`，每次成功连接后重置 `m_reconnectCount = 0` | P0 | core/ConnectionController | `enableAutoReconnect(true, 3000, 5)` 后 `m_maxReconnectRetries == 5`；成功连接后 `m_reconnectCount == 0` |
| R2 | **onAutoReconnect() 实现重试上限逻辑**: 进入时递增 `m_reconnectCount`，发射 `reconnectAttempt(m_reconnectCount, m_maxReconnectRetries)` 信号。若 `m_maxReconnectRetries > 0 && m_reconnectCount >= m_maxReconnectRetries`，停止重连定时器并发射 `connectionFailed(tr("自动重连"), tr("已达到最大重试次数(%1)，请手动重新连接").arg(m_maxReconnectRetries))` | P0 | core/ConnectionController | 设置 maxRetries=3 后，重连3次后定时器自动停止；maxRetries=0 时仍然无限重连 |
| R3 | **状态栏重连进度指示**: 在 MainWindow::connectThemeSignals()（或 connectSerialSignals()）中连接 `ConnectionController::reconnectAttempt` 信号，更新状态栏 `m_connStatusLbl` 显示"重连中 (2/5)..."格式文本，并使用 `state="reconnecting"` 动态属性驱动呼吸动画 | P1 | core/MainWindow + core/ConnectionController | 重连时状态栏显示"重连中 (1/3)..."并呼吸闪烁；达到上限后停止闪烁恢复"未连接" |
| R4 | **重连 Toast 通知**: 连接 `reconnectAttempt` 信号，发射 Toast 显示"正在尝试重连 (第N次)..."（Info类型，非防抖，2秒显示）；达到上限时 Toast 显示"自动重连已停止，已达最大重试次数"（Error类型） | P1 | core/MainWindowSignalConnect | 重连过程中有 Toast 提示；达到上限后有明确的失败 Toast |
| R5 | **ConnectionState 新增 Reconnecting 状态**: 在 `ConnectionState` 枚举中新增 `Reconnecting` 值，`handleConnectionState()` 中处理该状态显示对应的中文文本和视觉样式 | P1 | core/Constants + core/MainWindow | 状态栏在重连阶段有独立的视觉表现，区别于 Connecting 和 Disconnected |

### 实现方案

**R1 成员变量** (ConnectionController.h private 区域):

```cpp
int m_reconnectCount = 0;            ///< 当前自动重连尝试次数
int m_maxReconnectRetries = 0;       ///< 最大自动重连次数(0=无限制)
```

**R2 onAutoReconnect() 改造** (ConnectionController.cpp):

```
现有入口检查 -> 新增: m_reconnectCount++ -> emit reconnectAttempt() ->
检查是否达到上限 -> 是: 停止定时器 + 发射 connectionFailed ->
否: 继续执行原有的 connectSerial/connectNetwork 逻辑
```

在 `connectSerial()` / `connectNetwork()` 成功分支（`connectionSucceeded` 发射后），重置 `m_reconnectCount = 0`。注意重置应在 `onConnectionStateChanged(Connected)` 分支中执行，因为网络连接（TCP Client）是异步的，`open()` 返回 true 并不代表连接已建立。

**R3/R4 信号连接** (MainWindowSignalConnect.cpp):

在 `connectSerialSignals()` 中添加:
- `reconnectAttempt` -> lambda 更新状态栏文本 + 启动呼吸动画
- `reconnectAttempt` -> lambda 显示 Toast

**R5 ConnectionState 扩展**:

在 `core/Constants.h` 的 `ConnectionState` 枚举中新增 `Reconnecting`。在 `MainWindow::handleConnectionState()` 的 switch 中新增 case 分支，显示"重连中..."文本，`stateStr = "reconnecting"`，启动呼吸动画。

## 第二部分: DataExporter.cpp 预防性瘦身 (P1)

### 现状

| 方法类别 | 方法数 | 特征 |
|---------|--------|------|
| 全量导出 | 5 (exportPlain/HexDump/Csv/Timestamped/Bin) | 每个方法重复"打开文件->检查错误->写入->flushAndCheck"模式 |
| 流式导出 | 5 (exportStreamedPlain/HexDump/Csv/Timestamped/Bin) | 与全量导出格式相同的写入逻辑，但分批读取 |
| EDL范围 | 2 (exportRange/readEdlRange) | EDL二进制解析，逻辑独立 |
| 辅助 | 4 (flushAndCheck/filterByTime/toAsciiString/concatData/formatHexDumpLine) | 工具方法 |
| 总计 | 16方法, 498行 | 5个全量导出 + 5个流式导出的写入格式逻辑完全重复 |

核心问题: 全量导出的 5 个方法和流式导出的 5 个方法中，格式化逻辑是重复的。例如 `exportPlain` 和 `exportStreamedPlain` 都用 `"[%1] [%2] %3 | %4"` 格式化每一行，区别仅在于数据来源（内存 QVector vs LineProvider 回调）。提取格式化为独立方法可消除重复。

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R6 | **提取行格式化方法**: 将5种格式的单行格式化逻辑提取为静态方法: `formatPlainLine()`、`formatCsvLine()`、`formatTimestampedLine()`。全量导出和流式导出共用同一组格式化方法 | P1 | utils/DataExporter | exportPlain 和 exportStreamedPlain 调用同一个 formatPlainLine；代码行数减少 |
| R7 | **提取文件打开公共方法**: 将 `QFile file(path); if (!file.open(...)) { emit exportError(...); return false; }` + `QTextStream out(&file); out.setEncoding(...)` 提取为 `openTextFile(path, file, out)` 方法，消除10处文件打开的重复代码 | P1 | utils/DataExporter | openTextFile 返回 bool，内含错误检查和 exportError 发射；10处文件打开统一调用 |
| R8 | **DataExporter.cpp 行数降至 480 行以下**: 通过 R6+R7 的重构，确保最终行数 <= 480，为后续功能扩展留出安全余量 | P1 | utils/DataExporter | `wc -l DataExporter.cpp` 输出 <= 480 |

### 拆分方案

**R6 格式化方法提取**:

```cpp
// 新增私有静态方法（在 .h 中声明）
static QString formatPlainLine(const TerminalLine& line);    ///< [时间] [方向] HEX | ASCII
static QString formatCsvLine(const TerminalLine& line);      ///< 时间,方向,hex,"ascii"
static QString formatTimestampedLine(const TerminalLine& line); ///< [时间] HEX
```

`exportPlain` 的循环体从:
```cpp
out << QString("[%1] [%2] %3 | %4\n")
        .arg(timeStr, dirStr, HexConverter::toHexString(line.data), toAsciiString(line.data));
```
变为:
```cpp
out << formatPlainLine(line) << '\n';
```

`exportStreamedPlain` 也调用相同的 `formatPlainLine(line)`。

**R7 文件打开提取**:

```cpp
/**
 * @brief 打开文本文件并创建 UTF-8 文本流
 * @param path 文件路径
 * @param file QFile 对象引用（调用方栈变量）
 * @param out QTextStream 对象引用（调用方栈变量）
 * @return true=打开成功，false=打开失败（已发射 exportError 信号）
 */
bool DataExporter::openTextFile(const QString& path, QFile& file, QTextStream& out)
{
    if (!file.open(QIODevice::WriteOnly | QIODevice::Text)) {
        emit exportError(path, tr("无法打开文件: %1").arg(file.errorString()));
        return false;
    }
    out.setDevice(&file);
    out.setEncoding(QStringConverter::Utf8);
    return true;
}
```

10 个文本导出方法（5全量 + 5流式，Bin 除外）都使用此方法，每处节省约 3 行。

## 第三部分: 连接超时可配置 (P2)

### 现状

`ConnectionController.h` 第151行:
```cpp
static constexpr int kConnectionTimeoutMs = 5000; ///< 超时阈值 5 秒
```

硬编码为 `static constexpr`，编译期固定。所有连接类型共用同一超时值。

### 需求列表

| ID | 需求描述 | 优先级 | 涉及模块 | 验收标准 |
|----|---------|--------|---------|---------|
| R9 | **连接超时改为可配置成员变量**: 将 `kConnectionTimeoutMs` 从 `static constexpr` 改为普通 `int m_connectionTimeoutMs = 5000` 成员变量。新增 `setConnectionTimeout(int ms)` 和 `connectionTimeout()` 方法 | P2 | core/ConnectionController | 默认值仍为 5000ms；调用 `setConnectionTimeout(10000)` 后超时变为 10 秒 |
| R10 | **超时值持久化到 SettingsManager**: `setConnectionTimeout()` 调用 `SettingsManager::instance().set("connection/timeoutMs", ms)` 保存。构造函数中从设置恢复 | P2 | core/ConnectionController | 重启应用后超时值保持上次设置 |

### 实现方案

**ConnectionController.h 修改**:

```cpp
// 删除:
static constexpr int kConnectionTimeoutMs = 5000;

// 新增:
public:
    void setConnectionTimeout(int ms);    ///< 设置连接超时(毫秒)，最小1000，最大30000
    int connectionTimeout() const;        ///< 获取当前超时值
private:
    int m_connectionTimeoutMs = 5000;     ///< 连接超时阈值(毫秒)，可通过设置持久化
```

所有引用 `kConnectionTimeoutMs` 的位置改为 `m_connectionTimeoutMs`。值域校验: `qBound(1000, ms, 30000)`。

构造函数中恢复:
```cpp
m_connectionTimeoutMs = SettingsManager::instance().get("connection/timeoutMs", 5000).toInt();
```

> 注: 本次迭代不添加 UI 配置入口（Settings面板中无超时输入框）。超时值通过 SettingsManager 直接配置即可，后续迭代按需添加 UI。

### 翻译覆盖清单

`QAbstractSocket::SocketError` 常见错误码翻译:

| 错误码 | 中文翻译 |
|--------|---------|
| ConnectionRefusedError | "连接被拒绝。目标主机 %1:%2 未运行服务或端口未开放，请检查服务端程序是否启动" |
| RemoteHostClosedError | "远程主机 %1:%2 已关闭连接。服务端可能已停止或崩溃" |
| HostNotFoundError | "无法解析主机名 %1。请检查IP地址是否正确、网络是否连通" |
| NetworkError | "网络错误: %1。请检查网线连接或Wi-Fi状态" |
| SocketTimeoutError | "连接超时。目标 %1:%2 在 %3 秒内未响应，请检查网络连通性" |
| SocketAccessError | "Socket访问被拒绝。端口 %1 可能需要管理员权限或已被占用" |
| SocketResourceError | "系统资源不足，无法创建Socket。请关闭部分应用后重试" |
| DatagramTooLargeError | "数据报过大(UDP最大约64KB)。请减少单次发送数据量" |
| AddressInUseError | "端口 %1 已被其他程序占用。请更换端口或关闭占用程序" |

### 实现方案

**方案选择**: 提取到公共工具函数。

新建 `src/utils/NetworkErrorTranslator.h`（仅头文件，纯函数）:

```cpp
namespace NetworkErrorTranslator {
    /**
     * @brief 将 QAbstractSocket 错误码翻译为中文描述
     * @param error Socket 错误码
     * @param systemError Qt 提供的系统错误字符串（作为补充信息）
     * @param context 上下文信息（如 "TCP:192.168.1.1:8080" 或 "UDP:8888"）
     * @return 人类可读的中文错误描述
     */
    QString translateSocketError(QAbstractSocket::SocketError error,
                                  const QString& systemError,
                                  const QString& context);
}
```

`TcpConnection::onSocketError()` 改为:
```cpp
void TcpConnection::onSocketError(QAbstractSocket::SocketError error) {
    QTcpSocket* sock = qobject_cast<QTcpSocket*>(sender());
    QString sysErr = sock ? sock->errorString() : QString();
    QString msg = NetworkErrorTranslator::translateSocketError(error, sysErr, name());
    emit errorOccurred(msg);
    updateState(ConnectionState::Error);
}
```

`UdpConnection::onError()` 同理。
