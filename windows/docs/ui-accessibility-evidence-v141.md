# UI Accessibility Evidence v141

日期：2026-08-12

## 变更范围

本轮修复移动端 `05 / WORK SIGNAL` 表单的字段标题排版。原始 DOM 中 `label` 是 grid 容器，标题文本和 `.optional` 提示分别成为两个 grid item，导致“效率评分 / 项目 / 正确码 / 错误码”等提示被挤到第二行；390px 下这些字段高度为约 108px，表单阅读节奏被不必要地拉长。

共享 `ui-polish.css` 现在只对 `.activity-capture-card label:has(.optional)` 建立两列标题轨道：标题占据剩余宽度，提示靠右同排；输入框、文本域和 select 跨满下一行。业务字段、校验、DOM、脚本、接口和数据流均未改变。

## 可访问性与降级

- `.optional` 仍是标签内容的一部分，屏幕阅读器文本和表单关联关系不变。
- 输入控件继续作为 `label` 的直接后代，不引入额外焦点节点或 tabindex。
- `:has()` 只改变支持该选择器的现代浏览器布局；不支持时回退为原有可用的单列标签布局，不影响输入可达性。
- `prefers-reduced-motion`、`forced-colors`、透明顶栏和场景动效规则未被覆盖。
- 修改后文件仍低于 1000 行：`ui-polish.css` 984 行，`style.css` 674 行，`responsive-tuning.css` 693 行。
