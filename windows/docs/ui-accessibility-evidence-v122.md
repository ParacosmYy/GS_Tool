# UI 可访问性与视觉证据 · v122

## 变更主题

本轮收紧 Dashboard 在 `620px` 以下的首屏观测节奏：将 orbit 从“占满首屏的纵向 spacer”收敛为视觉锚点，减少 hero stage 的无效高度，并让标题、说明、主要入口和周期游标连续进入第一次扫描范围。基础 `style.css` 与完整样式链中的 `responsive-tuning.css` 保持同一契约，兼容当前个人入口与完整模板。

用户服务：`127.0.0.1:5000`。验证期间未重启或修改受保护的 `5000/5011` 服务，也未改变数据库、认证、Provider Key 或业务数据。

## 浏览器证据

- 使用本地隔离体验账号进入真实 Dashboard 页面，完成 `320×720`、`320×844`、`390×844`、`768×900`、`1024×900`、`1440×900` 六档几何检查；所有档位 `document.documentElement.scrollWidth - innerWidth = 0`。
- `390×844` 最终首屏：hero 高度约 `781px`，orbit 为 `280×280px`，主要入口约从 `y=694` 开始，周期控制约从 `y=795` 开始；相较本轮前的 hero `920px`、入口 `y=788`、周期控制 `y=927`，用户不再需要先穿过一段空白才能看到操作线索。
- `320×720` 最终首屏：主要入口约从 `y=640` 开始，周期控制约从 `y=741` 开始。周期控制在极矮视口中自然位于下一小段滚动内容，不被遮挡、不发生横向溢出；`320×844` 与 `390×844` 均能在首屏底部看到周期控制。
- `768×900`、`1024×900`、`1440×900` 的桌面/窄桌面场景保持既有轨道、标题和分析区构图；本轮变更只命中 `620px` 以下移动媒体查询。
- 点击 `Week` 后按钮 `aria-pressed=true`，页面状态文案为“已更新：本周”；应用日志为空，未发现页面级 console error/warn。
- Dashboard 保持 `1 个 h1 / 8 个 h2`；空态分析图表与自动采集入口在深滚位置仍可读，v122 未改变图表接口或数据契约。

## 工程与无障碍协议

- 只调整响应式 CSS，不新增 DOM、依赖、事件监听器、网络请求、认证逻辑或数据状态。
- orbit 使用视口上限，hero stage 取消移动端多余的最小高度；桌面轨道、`prefers-reduced-motion`、`forced-colors`、原生焦点和表单语义保持原有边界。
- 基础 `style.css` 共 `587` 行，`responsive-tuning.css` 共 `691` 行，均未超过项目每文件 1000 行约束。
- 两层样式保留同一移动契约，避免旧个人入口只加载基础样式时回退到旧的长首屏。

## 角色复核

- UI：首屏先建立“总量轨道 → 当前观测任务 → 周期控制”的连续阅读顺序，降低移动端视觉疲劳和无效滚动。
- 前端：变化限定在共享 Dashboard 响应式展示层，没有触碰模板语义、周期按钮脚本、API 或状态管理。
- 后端：无后端、数据库、认证、Provider、Key 生命周期或数据流改动；保护端口 `5000/5011` 未触碰。
- 架构师：变化归属 `03-observatory` 的响应式表现边界，基础层与完整样式层保持同契约；无新依赖、无跨模块耦合，回滚边界为 v122 两个媒体查询块。

## 未关闭门禁

真实设备、辅助偏好、Provider 联调、Android/EXE 构建、正式 HTTPS 与部署验收仍按项目总门禁执行，本证据不替代这些门禁。
