# ADR-058：Gateway 响应读取与幂等键可靠性边界

## 状态

已接受（2026-08-10）。

## 背景

本地 Gateway 使用流式 HTTP 读取上游 JSON/SSE。上游可能在返回状态码后中断连接，也可能返回
重定向。客户端还可能在网络重试时复用 `Idempotency-Key`；如果非法键被静默替换，第一次和第二次
调用会进入不同的中心去重键，造成重复入账风险。

## 决策

- 模型发现先判断 3xx 并关闭响应，再读取正文；任何上游响应体读取过程中的网络异常都统一映射为
  `502 UPSTREAM_UNAVAILABLE`，不让异常穿透为 Flask 500。
- 非流式成功响应和上游错误响应复用相同的网络读取边界。读取失败不会伪造 usage，也不会把
  provider 响应正文写入日志或错误包络。
- Gateway 允许缺省 `Idempotency-Key`，为该次调用生成 `gateway-<uuid>`；客户端提供的键必须不超过
  160 个字符且不能含 ASCII 控制字符。非法键在 provider 调用前返回 `400 PROVIDER_INPUT_INVALID`。
- 通过校验的键在非流式、流式和重试队列全链路保持不变；队列解密时再次拒绝控制字符，防止内部
  header 注入边界被绕过。

## 取舍

这会把部分原本可能进入上游的非法请求提前拒绝，但换来了可预测的失败语义和可靠的幂等入账。缺省
键仍保持对普通 OpenAI-compatible 客户端的兼容；需要跨请求重试去重的客户端应显式生成稳定键。

## 验证边界

- 已完成：源码分支审计、编译检查和隔离的配置/解析 smoke；真实 provider 的断连、重定向和合法
  Key 联调仍需用户授权的上游环境。
