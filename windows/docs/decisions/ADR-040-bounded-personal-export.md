# ADR-040：个人 CSV 复用共享有界导出边界

## 状态

已接受（2026-08-10）。

## 背景

个人 Web `/api/export` 和 CLI 原先直接消费 `db.export_csv()` 的 `fetchall()` 结果。虽然
个人数据范围比管理员小，但用户仍可能长期积累大量调用记录，不能把“只属于本人”误当作
内存预算。管理员导出已经需要固定的行数/字节边界，两个出口继续各自维护序列化逻辑会产生漂移。

## 决策

1. 新增 `csv_export.py` 作为共享 Infrastructure 序列化边界，固定最多 100,000 行和 16 MiB，
   使用 UTF-8 BOM、游标逐行消费和固定列投影。
2. `admin_data.py` 与 `db.py` 只负责查询/投影，不负责重复实现 CSV 缓冲和大小计算。
3. 个人 Web/API 超限返回统一 `413 EXPORT_TOO_LARGE`；CLI 在写文件前完成导出，超限时
   返回错误码且不写入半成品文件。既有字段、时间范围和 BOM 行为保持不变。
4. 后续若需要更大导出，优先新增按时间/用户/游标分页契约，不移除共享边界。

## 取舍

- 共享序列化器返回受限 bytes，Web 不再二次编码；这是内部模块接口变化，HTTP CSV 契约保持兼容。
- 16 MiB/100,000 行是当前本地 SQLite 的保守出口预算；真正低峰值的响应流式传输仍可在不改字段
  契约的前提下单独设计。

## 性能证据

- 基线结构检查：个人 `db.export_csv()` 额外存在 `fetchall()` 和无界 `StringIO`。
- 变更后结构检查：个人与管理员查询都把单次游标交给 `csv_export.export_rows()`，共享边界只
  定义一份；三类管理员投影和空个人投影运行态均输出合法 BOM CSV。
- 验证门禁：Python 编译、依赖检查、CLI help、静态 `fetchall()` 边界扫描和临时空 schema 冒烟；
  不创建项目测试数据，不读取真实数据库内容。
