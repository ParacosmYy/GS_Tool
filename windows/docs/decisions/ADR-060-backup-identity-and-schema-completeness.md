# ADR-060：备份身份唯一性与当前 schema 完整性

## 状态

已接受（2026-08-10）。

## 背景

备份文件以本地时间秒级命名。短时间内重复运行命令时，如果候选文件名已经存在，简单的 PID
回退仍可能再次命中旧文件；而项目新增 `usage_ingest_tokens` 后，旧验证清单没有把该表列为当前
可恢复能力的一部分。

## 决策

- `create_backup` 在目标已存在时追加进程号和随机短后缀，并持续检查候选名；不会因为同一秒重复
  执行而覆盖已有备份。
- `verify_backup` 的必要表清单必须覆盖当前生产 schema，包括账户、用量、bearer token、Usage
  Ingest Token、工作事件、应用日志、审计事件和共享限流状态。
- 缺少当前必要表的副本直接验证失败；恢复前仍必须执行完整 integrity/foreign-key/schema 校验。

## 取舍

备份文件名不再完全由时间决定，但更适合审计和保留策略；旧版本副本可能因为缺少新增表而无法
直接作为当前版本恢复源，管理员需要在迁移流程中明确处理，而不是把不完整副本误当作可用恢复点。

## 验证边界

- 已完成：源码审计、Python 编译、只读发布审计和文件规模门禁。
- 待完成：正式数据保留周期、真实数据恢复负责人记录和部署主机回滚演练。
