# ADR-008：企业级模块化单体作为当前基线

**作者：** AI Token Tracker Engineering Team  
**维护者：** Project Owner  
**状态：** Accepted  
**日期：** 2026-08-10

## 决策

当前版本不直接拆成 Go/Vue 微服务，而是把 Flask 应用改造成可拆分的模块化单体：Presentation、Application、Domain ports、Provider boundary、Infrastructure 五层，新增能力必须放入职责明确的模块并通过显式接口连接。

## 原因

- 项目当前核心复杂度在权限、数据隔离、自动采集和 UI 体验，不在跨服务通信。
- 单机 SQLite 与 Windows 中心服务是用户明确要求；直接微服务会引入数据库网络化、部署、监控和备份复杂度。
- `/api/v1`、DTO、错误码、事件幂等和审计边界已经为未来 Go/Vue/Android 留出稳定迁移面。

## 企业工程原则

- 契约先行：API、事件、错误码和安全边界先文档后代码。
- 依赖倒置：路由只编排，用例不依赖模板，请求上下文不进入仓储。
- 领域隔离：token 事实、工作效率、排障日志和安全审计分开建模。
- 默认拒绝：认证、RBAC、provider 白名单、CSRF、限流和输入校验都由服务端强制。
- 可观测交付：request id、结构化日志、审计和运行证据一起交付。
- 可回滚演进：数据库迁移只做加法；API 破坏性变更新建主版本。

## 不做的事

- 不把所有功能合并到一个千行路由文件。
- 不为“看起来像大厂”而提前引入微服务、消息队列或 Kubernetes。
- 不把效率评分当作同学绩效结论；产品只记录用户明确提交的事实和可解释指标。
- 不宣称已经完成生产安全、合规或大规模性能验证；这些需要独立环境和证据。
