# ADR-033：HTTPS 边缘配置的只读预检边界

## 状态

已接受（2026-08-10）。

## 背景

正式分享入口由 Caddy 终止 HTTPS，并把请求反代到仅监听 `127.0.0.1` 的 Waitress。
仅执行 `caddy run` 无法保证配置文件有效、日志目录存在或日志文件不会被本机宽泛账户修改；
自动安装软件、申请证书、改防火墙和改 ACL 又需要项目负责人明确授权，不能被普通体验入口隐式执行。

## 决策

新增 `deployment/preflight-edge.ps1`，要求调用者显式提供 Caddyfile 和日志目录。它按以下顺序
执行只读检查：

1. 检查 `caddy` 可执行文件存在；
2. 检查 Caddyfile 和日志目录存在且类型正确；
3. 使用 `FileSystemRights` 位掩码检查日志目录以及其中已有的每个日志文件，拒绝
   `Everyone`/`BUILTIN\Users` 等宽泛主体的写入、创建、删除、修改权限或完全控制权限；
4. 调用 `caddy validate --config ... --adapter caddyfile`；
5. 仅在所有检查通过后输出可供人工继续使用的结果，不启动 Caddy。

## 取舍与边界

- 预检不能证明域名 DNS、证书签发、外部 HTTPS、Windows 服务生命周期或真实访问日志内容；
  这些仍需正式环境演练。
- ACL 主体名称以常见 Windows SID/名称为最低保护线；组织自定义服务账户和更严格的继承策略
  仍需由部署负责人复核。
- 脚本故意不创建日志目录，防止错误路径导致静默建目录或权限继承。

## 验证

- 当前环境没有安装 Caddy，因此真实 `caddy validate` 未执行；脚本会在缺少 Caddy 时 fail-closed。
- 脚本文本包含严格错误处理、显式参数和无写入操作；项目 Python 编译/文件行数门禁继续执行。
