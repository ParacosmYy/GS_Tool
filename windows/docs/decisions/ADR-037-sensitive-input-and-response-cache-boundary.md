# ADR-037：敏感输入与响应缓存的统一安全边界

## 状态

已接受（2026-08-10）。

## 背景

中心服务同时接收账户密码、工作事件、诊断日志、Provider 响应和跨端 token 请求。
这些输入可能被浏览器缓存、写入结构化日志或在管理员观测台展示。仅依赖前端提示或对已
序列化 JSON 做字符串替换，无法稳定保证敏感值被遮蔽，也可能产生不可解析的 metadata。

## 决策

1. 账户密码在注册和认证边界统一限制为 8-256 个字符；过长输入直接失败，避免把资源
   预算交给密码哈希和请求体。
2. `events.py` 在持久化前按敏感键名和凭据样式脱敏项目名、任务类型、备注、日志消息与
   metadata 值；metadata 先构造受限对象再 JSON 编码，超过 4000 字节时保留合法 JSON 的
   `_truncated` 标记，不对序列化 JSON 做破坏性正则替换。
3. 登录、注册、仪表盘、管理员页面、所有 `/api/` 和 `/api/v1/` 响应统一使用
   `Cache-Control: no-store`、`Pragma: no-cache` 和 `Expires: 0`，防止浏览器或共享代理
   保留账户投影、Provider 响应和 token exchange 内容。

## 取舍

- 日志中的部分普通文本可能被保守地替换为 `[REDACTED]`，换取不把凭据暴露给管理员导出
  或日志查看器。
- 256 字符密码上限是资源边界，不代表密码必须短；用户仍应使用密码管理器生成强密码。
- `no-store` 会减少浏览器缓存命中，但认证和用量数据优先保证隐私与撤销语义。

## 验证

- 通过 Python 直接冒烟验证 `Authorization: Bearer ...`、`api_key`、`sk-...` 文本会被
  脱敏，长 metadata 仍可被 `json.loads` 解析且不超过 4000 字节。
- 通过密码边界冒烟验证 8-256 字符可进入验证路径，超过上限被拒绝。
- 通过应用源码和 HTTP 头检查确认认证/API 路径具备 `no-store` 边界。
