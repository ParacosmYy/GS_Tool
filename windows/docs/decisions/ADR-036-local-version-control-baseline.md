# ADR-036：建立当前 checkout 的本地版本控制基线

## 状态

已接受（2026-08-10）。

## 背景

项目已经包含 Windows 端、Android 端、分层源码、部署脚本和多项架构决策，但此前没有
Git 元数据。因此无法可靠执行变更审查、确认忽略规则是否生效，或为后续交付保留可回滚
的本地保存点。项目约束要求所有工作留在当前 checkout，且禁止创建或操作 worktree。

## 决策

在项目根目录初始化单一 Git 仓库，使用 `main` 作为当前本地基线分支；不配置远程仓库、
不推送、不创建 worktree。首次提交只包含可复现的源码、配置样例和工程文档，以下内容由
根 `.gitignore` 排除：

- `.env`、真实密钥和运行时凭据；
- SQLite 主库、备份、staging 文件及 SQLite journal/WAL 文件；
- 虚拟环境、缓存、构建产物和部署日志；
- 真实 Caddyfile。

数据库备份与恢复仍由应用命令负责，Git 只保存代码和决策记录，不替代数据备份机制。

## 备选方案

### 不建立版本库

- 优点：没有额外元数据。
- 缺点：无法审查忽略规则或建立可回滚保存点。
- 拒绝：与企业级交付和回滚证据要求冲突。

### 配置远程仓库并推送

- 优点：具备异地协作和远程备份能力。
- 缺点：会扩大数据暴露面，且当前没有明确的远程仓库、访问控制和发布授权。
- 暂不采用：先完成本地基线；远程协作必须另行确认仓库、权限和隐私边界。

## 后果

- 后续每个可交付切片都可以通过提交形成可审查、可回滚的保存点。
- Git 忽略规则可以用 `git check-ignore` 做真实验证，而不只是静态阅读。
- 首次提交不会包含已有本地用量数据；用户仍需按项目备份流程保护数据库。
- Android 构建、正式 HTTPS 和远程共享仍是独立的环境/部署门禁，不因本地 Git 基线而被
  误判为已完成。

## 验证

- 仓库只在当前 `ai-token-tracker` checkout 初始化。
- 忽略规则命中数据库、`.env`、真实 Caddyfile 和部署日志路径。
- 提交前检查 staged 文件名，确认不包含敏感数据、缓存、虚拟环境或构建产物。
