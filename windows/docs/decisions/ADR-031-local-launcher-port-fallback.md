# ADR-031：个人体验入口的端口回退策略

## 状态

已接受（2026-08-10）。

## 背景

根目录 `start.bat` 是用户随时体验当前源码的入口。Windows 上可能已经有旧版本
开发服务占用 `127.0.0.1:5000`；如果入口仍然固定打开 5000，新进程会因为地址冲突退出，
浏览器却会继续显示旧页面，造成“代码已经更新但页面没有变化”的误判。自动化终止占用端口的
进程又可能破坏用户正在使用的服务或会话，因此不属于个人体验入口的授权范围。

## 决策

1. `windows/run.py` 默认尝试 5000；端口不可用时按 5001–5020 顺序选择可用端口。
2. 启动器只做无副作用的 socket 探测，不启用可能掩盖 Windows 监听状态的
   `SO_REUSEADDR`，也不查询、不终止、不重启端口占用进程。
3. 启动日志必须打印实际地址；浏览器只打开当前进程实际选择的地址。
4. `TOKEN_TRACKER_PORT` 仍可显式指定首选端口。生产和局域网启动继续由 CLI 的显式
   `--port`、Waitress 和部署预检负责，不复用这个个人体验回退策略。
5. 根目录 `run.py` 只负责把 Python 调用转发到 `windows/run.py`，不复制端口选择、Flask 组合或
   业务逻辑；`start.bat` 仍是非开发用户的首选入口。

## 取舍

- 个人双击体验在旧服务残留时仍能打开最新源码，但地址可能从 5000 变为 5001 等端口。
- 端口探测与真正监听之间存在极短竞态；若竞态发生，底层服务器仍会报告绑定错误，用户可
  重新启动或显式设置端口。该策略不替代正式进程管理器。
- 端口范围故意保持很小且确定，避免在本机环境中无边界扫描端口。

## 验证

- `python -m compileall -q token_tracker` 通过。
- 启动入口在 5000 被占用时的选择逻辑通过隔离 socket 冒烟验证；验证不会终止现有服务。
- 根目录与 `windows/start.bat` 的文档已同步，启动窗口不再硬编码“浏览器一定打开 5000”。
