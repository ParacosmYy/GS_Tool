# ADR-059：Gateway 传输与重试元数据完整性

## 状态

已接受（2026-08-10）。

## 背景

Gateway 的 `--allow-http` 只适合本机调试：如果它与 `0.0.0.0` 或可信局域网监听同时出现，客户端
到本地代理的 provider 请求和凭据占位链路会缺少传输加密。另一方面，DPAPI 只保护队列 payload；
SQLite 中的行数、尝试次数和调度时间仍然是可被同用户文件权限范围内篡改的元数据，不能把它们当成
天然可信输入。

## 决策

- Gateway 在非 loopback 地址上拒绝 `allow_http=True`，只有 loopback 调试允许 HTTP；共享访问必须
  由 HTTPS 边缘或其他受控传输层承担。
- 队列启动时先检查总行数不超过配置容量，再校验每行尝试次数在 1–20、下一次执行时间为有限数，
  最后解密并验证 payload。任何异常都 fail-closed，不静默丢弃或重置队列。
- 新增和重排队列项目同样拒绝 NaN/Infinity 调度时间，避免 worker 永久睡眠或忙循环。

## 取舍

本机以外的临时 HTTP 预览会被明确拒绝；需要同学共享时应先完成 HTTPS edge 配置。队列元数据损坏
会阻止 Gateway 启动，代价是需要人工恢复/迁移，但不会在不确定调度状态下重复或丢失入账事实。

## 验证边界

- 已完成：配置分支、队列边界源码审计、Python 编译和只读发布审计。
- 待完成：正式 HTTPS edge、真实 provider Key 以及部署主机上的损坏队列恢复演练。
