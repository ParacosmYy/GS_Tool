# ADR-074：场景背景可见度与内容安全区调校

**作者：** AI Token Tracker Engineering Team  
**维护者：** UI-1 / DEV-1 / ARCH-2  
**状态：** Accepted  
**日期：** 2026-08-10

> 历史说明：本 ADR 固化 v9 的遮罩与可见度调校基线；当前默认场景资产已由 ADR-076 切换为 v10，
> 但其左侧文案安全区、右侧信息层级和动效降级约束继续沿用。

## 背景

v9 场景资产已经表达御姐风格的二次元嵌入式工程师、银色 Pro 形态笔记本、桌面工作站、示波器、
开发板和 Rust/RL 监控屏。但运行时截图显示，旧遮罩把右侧场景压成了几乎不可辨认的暗纹理，
用户看不到背景为何与产品主题相关。左侧首屏标题和认证表单又必须维持稳定的正文对比度。

## 决策

1. 不更换 v9 像素资产；只在 `scene-motion.css` 调整场景滤镜和黑色遮罩梯度。
2. 左侧保留高不透明度的内容安全区，右侧逐步降低遮罩透明度，让角色、笔记本、桌面工作站和
   示波器形成可辨识的品牌叙事。
3. 普通模式只提高场景亮度、饱和度和对比度，不新增持续高成本动画；既有 `backdrop-glow` 和
   `backdrop-scan` 仍表达环境光与信号扫描，分别保持 16 秒和 13 秒周期。
4. `prefers-reduced-motion`、`prefers-contrast: more`、`forced-colors: active` 和窄屏规则继续
   独立接管场景；背景始终 `pointer-events: none`，不参与焦点、语义或业务点击。

## 取舍与后果

- 桌面登录页的右侧场景更清楚，产品主题不再依赖用户“猜”背景内容。
- 左侧标题和表单仍使用独立内容层，不把图片可读性当作业务信息来源。
- 场景更亮会增加视觉存在感，因此不把同一策略无条件复制到高对比度和强制系统色模式。
- Android 不复用 Web CSS；继续使用同一 v9 资产和 Compose 自己的遮罩/低幅漂移策略。

## 回滚

回退 `scene-motion.css` 的可见度调校即可恢复上一版遮罩；不删除 v9 或 v8 资产，不改变 API、
认证、数据库和 Android 公共契约。

## 验证边界

- 临时源码实例 `127.0.0.1:5019` + 隔离 SQLite：登录页桌面截图确认角色脸部、笔记本、银色工作站
  和示波器可辨识，左侧标题、说明和认证卡片保持可读。
- DOM 只读检查确认 v9 PNG 已加载、场景滤镜为 `saturate(1.18) contrast(1.08) brightness(1.1)`，
  场景扫描动效保持 16s/13s。
- 本 ADR 不宣称真实设备、系统级 reduced-motion/高对比度或生产部署门禁完成；这些仍由 UI-3
  和最终发布矩阵独立验收。
