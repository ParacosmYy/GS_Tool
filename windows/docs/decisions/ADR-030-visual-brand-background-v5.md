# ADR-030：升级跨端嵌入式 Rust/RL 品牌背景 v5

## 状态

已接受（2026-08-10）。

## 背景

v4 已经解决了登录页左侧文字负空间和右侧工程场景的问题，但设备语义仍偏抽象。产品需要继续保持成熟、专业、可爱而不幼态的二次元工程师形象，并让 MacBook Pro、Mac Studio、嵌入式实验台与 Rust/RL 训练监控在首屏可被快速识别。

## 决策

1. 生成独立的 `embedded-rust-engineer-bg-v5.png`，不覆盖 v4，以保留可回滚资产。
2. Web 与 Android 使用同一份像素内容，分别放置在各端资源目录并通过各自的资源引用加载。
3. 角色、设备和高亮监控集中在右侧；左侧继续保留深色留白，正文遮罩优先于背景装饰。
4. 设备只呈现无品牌文字的产品化外形，屏幕内容采用抽象 Rust、嵌入式和 RL 图形，避免生成不可控的可读文字。
5. 继续保留低幅视差、扫描光和 reduced-motion 降级；视差使用背景定位而不是整体缩放，固定装饰收敛在视口内；背景永远 `pointer-events: none`，不参与业务交互。

## 影响

- Web 默认渲染切换为 v5，v4/v3/v2 仍可作为回滚资产。
- Android Compose 默认资源切换为 v5；APK 构建仍受 Android 工具链批准状态约束。
- 视觉资产体积随分辨率增加，需要在发布打包阶段执行图片压缩和缓存策略评估。

## 验证

- v5 图像已检查：右侧角色、MacBook Pro、Mac Studio 和实验室场景可识别，左侧无高亮主体。
- Windows/Android 两份 v5 文件 SHA-256 一致：`CD1AD0D1DD09E0DDE06531D68BACFDA19FA3BA2AE73ACAE8E26CBB5FE8BF3881`。
- Web v5 资源已通过隔离本地服务的 HTTP 200 校验；1440/1024/768/320 四断点真实浏览器截图、横向溢出检查和控制台检查已通过。截图与焦点证据记录在 `docs/ui-accessibility-evidence.md`。
