# ADR-064：仓库代码与文本文件行数门禁

## 状态

已接受（2026-08-10）。

## 背景

项目约束要求单文件不超过 1000 行，以保持高内聚、低耦合和可审阅性。仅扫描 Python、Kotlin
或 CSS 会漏掉 Gradle/Kotlin DSL、PowerShell、Markdown、YAML 和配置文本，不能证明仓库约束
真正覆盖交付物。

## 决策

- `token_tracker audit` 的 `source-line-cap` 同时扫描自有代码、脚本、配置和 Markdown 等项目
  文本文件；生成状态目录、虚拟环境、缓存、数据、构建、staging 和工具链保留目录不纳入扫描。
- 作者头门禁仍只检查自有代码/脚本扩展名，不要求第三方参考文档或普通文档伪装成源码头。
- 二进制资源不按文本行计数；跨端图片和 Chart.js 继续使用专门的 hash/供应链检查。

## 验证边界

- 已完成：当前 checkout 代码/文本文件全量行数扫描，未发现超过 1000 行的文件。
- 后续新增代码、配置或文档会在 `audit` 中自动受到相同门禁。

## 回滚

不得为绕过门禁而扩大忽略目录；如新增生成目录，必须在 ADR 和审计实现中记录其生命周期与
安全原因，并保留源文件行数约束。
