# UI-3 可访问性与视觉证据 v97

## 变更边界

- **问题**：`320×720` 的窄短手机上，仪表盘 hero stage 的轨道与文案占用过多垂直空间，两个首要操作按钮落在首屏底部之外。
- **实现**：`responsive-tuning.css` 增加 `max-width: 360px` 且 `max-height: 760px` 的独立首屏契约，仅收紧 hero 上下留白、轨道尺寸、lede 间距和 footer gap；桌面、平板和普通手机不进入该规则。
- **交互边界**：不改变 DOM、导航、API、认证、表单值、数据流或键盘顺序；按钮仍保持原来的两个并列动作。
- **文件边界**：变更集中在响应式表现层，`ui-polish.css` 保持 995 行，没有继续堆叠大型共享样式文件。

## 隔离浏览器观察

- 实例：`http://127.0.0.1:5193/dashboard`，隔离账号仅用于本地视觉观察。
- `320×720`：hero actions 从原先 `bottom ≈ 742` 收束至 `bottom = 698`，完整位于视口内；period control `bottom = 811`，页面继续保持自然滚动。
- 响应式矩阵：`320×720`、`360×740`、`390×844`、`768×900`、`1024×768`、`1440×900` 均无横向溢出，主操作区保持可见。
- 视觉状态：320px 截图确认背景场景、TOTAL SIGNAL 轨道、标题和两个主按钮层级连续，没有新增实心顶栏或遮罩。

## 可访问性与稳定性

- `320×720` 仪表盘：41 个交互控件，41 个具备可访问名称；标题结构为 1 个 `h1`、8 个 `h2`。
- 页面日志：清洁；浏览器工具自身的 Statsig 网络超时/丢弃事件不属于应用日志。
- 未在本轮宣称真实设备、`prefers-reduced-motion`、forced-colors 或真实 Provider Key 联调通过。
